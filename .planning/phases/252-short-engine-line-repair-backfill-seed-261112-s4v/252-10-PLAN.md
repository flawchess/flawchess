fix) and 252-CONTEXT.md D-16. The tier-4 lease leases node 0 (k = 0) and the worker or the server-pool blob-only tick
searches it with MultiPV-2, so a re-walked line gets its second move with no further code change.

    - the same blob at a node-0 position with exactly one legal move is not fed
    - blob[0] with s or sm present is not fed; an all-None node 0 (no best eval) is not fed; a `[]` blob and a NULL blob are not fed
    - node-0 ply above DEDUP_MAX_PLY is not fed (missed line: flaw ply; allowed line: flaw ply + 1)
    - guest games and games without full_evals_completed_at are not fed (D-13)
    - only the affected line of a flaw is NULLed; its other line stays (D-03)
    - idempotent: feeding the same window twice NULLs nothing new
    - `--pass node0` reads and writes its own work-list and feed-state files; the short-line files are byte-identical before and after
    - default pass: every pre-existing feed test passes unchanged

  <action>
Add `--pass {short,node0}` (default `short`) to the `feed` and `status` subcommands and thread it through `FeedOptions`.
For `node0`: select candidate lines in SQL (the node-0 ply bound, the array and node-0 key checks, the same eligible
joins as `_REWALK_ELIGIBLE_JOINS`), then filter in Python on legal move count at the node-0 board using the existing

`feed-<db>-<scope>-node0-<stamp>.md`. Named constants, no magic numbers; import DEDUP_MAX_PLY, do not re-declare it.
