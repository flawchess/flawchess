<objective>
Re-walk the repaired lines on prod through the tier-4 lane (S2) with the D-11 feeder, run the benchmark line repair on
the owner's box alongside it (D-09), and finish prod with the engine-free retag sweep (D-14).

DISPATCH OVERRIDE (read before spawning an executor): every task in this plan is a checkpoint (`checkpoint:decision`
or `checkpoint:human-action`, all `gate="blocking-human"`), so a gsd-executor spawned by execute-phase performs no
task action itself: it stops at the first checkpoint and returns control. The ORCHESTRATOR (top-level session) is the
actor for every checkpoint: it asks the owner where the task needs an owner answer, otherwise runs the task's action
in its own session (prod MCP access, long runs launched with setsid nohup and watched with Monitor), then resumes the
plan with the recorded results; the continuation executor only writes the SUMMARY from those results. Reasons: the
runs take hours to weeks, executor sessions die about 40 minutes into long DB-heavy runs and take their background
children with them, and subagents cannot use the flawchess-prod-db MCP (project memory).

Purpose: tactic tags and Train solution lines only change once the blobs are re-walked; the retag catches lines whose
pv changed without a re-walk (RESEARCH Pitfall 11).
Output: committed feed, benchmark-repair and retag reports.
</objective>
