## Decisions taken in this plan

- **A2 / orchestrator note 2 (cohort counting):** MIN/MAX and `n_users` count distinct users, not colour points. A
  user's two colour rates are correlated draws of one trait; counting points would overstate the cohort and halve the
  Elo span at the 500 cap compared with every other metric. Rated `costly`: changing it later means a regen of the
  two opening metrics, a reseed and a prod Stage B backfill. Recorded in the regen report header.
- **Orchestrator note 3 (scoped regen):** `--metrics opening_worse_rate,opening_better_rate`, merge mode, pinned
  `--snapshot-date 2026-05-30` (the basis of the committed CDFs; benchmark max played_at is 2026-05-26), separate
  report path. The ~10-minute run is a `checkpoint:human-action` executed inline by the orchestrator session (project
  memory: backgrounded executor runs die; executor SSE timeouts on long DB runs), and Task 1 is committed before it.
- **Per-eval-source check delivery:** deterministic code-path check already lives in plan 01
  (`-k eval_source`); the empirical part is a committed read-only report script, paired per user x colour x TC (project
  memory "Paired, not pooled, for cohort subset splits": pooled splits sign-flipped before). Numbers go in the SUMMARY,
  never into an assertion.
