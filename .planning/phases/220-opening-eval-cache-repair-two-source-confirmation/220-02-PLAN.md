<objective>
Close the second gap SEED-164 surfaced: the remote-worker submit lane reads the opening
dedup cache but never writes it (CACHEFIX-12), so ~85% of full-eval throughput never
reaches the cache and a remote-only lane (the benchmark DB) gets no opening dedup at all.
Also fix the non-deterministic `OPENING_CACHE_BACKFILL_SQL` donor choice, close the
lichess-eval provenance leak in the tick (RESEARCH open question 5, resolved below), and
land the CACHEFIX-09 integrity checks in the `db-report` skill.

Purpose: this is release-1 work that is independent of the repair pipeline and of the
two-source scheme, so it ships alongside them and gives the benchmark lane opening dedup
for the first time. Under CACHEFIX-08 (plan 07) it becomes the second confirmation source
without which two-source confirmation would starve in remote-heavy lanes.

Output: a submit that writes the cache, a deterministic backfill donor rule, a tick that
honours its own lichess provenance invariant, and two new sanity checks in the db-report
skill.
</objective>

## Decisions recorded by this plan

- **RESEARCH open question 5 resolved: YES, the tick leaks lichess-eval opening evals into
  the cache.** Verified in the tree 2026-09-09: `app/services/eval_drain.py` sets
  `dedup_hashes = []` for `is_lichess_eval_game`, so `dedup_map` is empty, so
  `engine_targets` contains every non-terminal opening ply, and the tick then passes
  `update_opening_cache=True` with `engine_targets_for_cache=engine_targets`
  unconditionally. The values written are genuine `evaluate_nodes_multipv2` results on
  hash-asserted boards, so this is a **provenance-rule violation, not a misalignment poison
  source** — but the file's own dedup-partition comment states lichess games are never
  donated to the cache (SEED-109 item 4), and `test_dedup_excludes_analyzed_source`
  enforces that rule only at the backfill-SQL gate. Fix: a one-line guard in the tick's
  cache arguments, plus a test. Noted in the CACHEFIX-07 report as an additional (small)
  provenance leak the phase closed.
- **RESEARCH assumption A5 resolved: no circular import.** `app/routers/eval_remote.py`
  already imports from `app.services.eval_drain`, and `eval_drain.py` imports only
  `app.schemas.eval_remote`, never the router.
- **Pitfall 2 (self-confirmation trap) is handled here, not deferred to plan 07.** Under
  first-write-wins the trap is a harmless no-op, but building the filter now means plan
  07's promotion logic inherits a target list that is already correct.
