<objective>
Make the repair auditable and answer the one open question the seed left: `report`
(CACHEFIX-07) turns the audit tables into a committed markdown trail with a verification
block that restates every baseline it is measured against, and `legacy-sample`
(CACHEFIX-10) measures whether the pre-2026-06-18 cohort also carries wrong-position evals

radius. Without `legacy-sample` the phase closes with an unanswered question the seed
explicitly refused to answer from the armchair.

Output: two read-only stages, a dated report under `reports/opening-cache-repair/`, and a
decision line that stands whichever way the numbers fall.

## Decisions recorded by this plan

- **D-07 implemented as its own `legacy-sample` subcommand, run after `report`**, gated on
  `calibrate_finished_at` (not on `report_finished_at`) so a yes/no that may build nothing
  never delays the repair. Cohorts: 200 games with `full_evals_completed_at < 2026-06-18`
  and `lichess_evals_at IS NULL`, walked across ALL plies at depth 15, plus a like-for-like
  control of 50 games with `full_evals_completed_at >= 2026-08-20` on the same walk. Per-row
  disagreement = expected-score delta beyond `screen_floor` or a mate/non-mate mismatch.
  Build rule stated in the code and printed in the decision line:
  `legacy_rate_ply_gt_20 > 2 * control_rate_ply_gt_20 AND (legacy_rate - control_rate) >= 1.0pp`.
  Reversibility: `reversible` — the sample is ~25 minutes of engine time and can be re-run
  with a different rule.
- **`screen --legacy-cohort` is NOT built in this plan.** D-07 says build it only if the
  sample's numbers demand it; the sample runs on prod in plan 06. If the verdict is build,
  that is a follow-up phase, recorded as such in plan 06's summary — not silently absorbed
  here.
- **RESEARCH Pitfall 10 honoured:** `reports/` is git-tracked except for four unrelated
  subpaths, so the report file WILL be committed — which is what CACHEFIX-07/11 want. The
  per-user table therefore carries user ids only.
- **The report distinguishes the two `pending` populations plan 01 separated:** rows
  `pending` with no carrier (`orphan` candidates) versus rows `pending` that DO have a
  carrier (the walk was cut short). Collapsing them would make the status accounting read
  complete when it is not.
