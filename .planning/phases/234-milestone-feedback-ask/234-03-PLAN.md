from, and "Sure!" opens an app-level feedback modal that survives Hilda disappearing underneath it and

"Sure!" path, split out of plans 01 and 02 to keep every plan inside the per-plan budget.

placeholder in feedbackAsk.ts, a new host component, two App.tsx mounts, the Sure handler change, and
extended bubble tests.

## Planning notes

- **Why one plan spans backend and frontend:** both tasks are the two ends of the same "Sure!"
  submission (UI -> POST /api/feedback -> feedback.source). Each task is small (five files), and the
  split keeps plans 01 and 02 below the per-plan file budget. The tracer verifies the server half
  through HTTP and re-runs the plan 02 FeedbackModal test that proves the client sends the field.
- **Discretion adopted (CONTEXT "Claude's Discretion"):** the app-level FeedbackModal host (RESEARCH
  Pitfall 1). The host fires no Umami event: the submission is a DB row carrying its source.
- **Sure ordering:** open the modal first, then POST done, so the dialog is up before the done
  response's cache patch unmounts the bubble.
