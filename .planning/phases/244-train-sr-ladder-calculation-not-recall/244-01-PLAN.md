## Decisions taken in this plan (planner, recorded per CONTEXT "Claude's Discretion" and the orchestrator notes)

- **D-02 overrides ROADMAP/SEED-207 snapping.** The ROADMAP test bullet "fail delay snaps to a scheduled weekday" and the
  SEED-207 sketch line are superseded; tests pin the NON-snapping behaviour (sparse mask still yields today+10 / today+4).
  `weekday_mask` is removed from `apply_result` entirely (the single call site makes removal proportionate);
  `next_scheduled_day` stays for `session_window` and `tick_days`.
- **D-11 overrides SEED-207's 14 days** (CORRECT_RETRY_DAYS = 10). **D-06** drops the streak remap.
- **Migration dates in UTC (Claude's discretion).** Solve day = `(solved_at AT TIME ZONE 'UTC')::date`, today =
  `(now() AT TIME ZONE 'UTC')::date`. Off by at most one day for non-UTC users (CONTEXT allows), and it never raises:
  Postgres `AT TIME ZONE` raises on an invalid stored IANA name, unlike `local_today`'s fallback.
- **D-09 made literal.** The UPDATE requires `floor > today_utc` as well as `due_date < floor`, so an overdue item whose
  floor is already past keeps its exact current due date (composition orders SR items by `due_date` ascending, so a
  later-but-still-past date would silently change priority). This also matches the CONTEXT prod sizing basis ("floor
  still in the future", ~436 rows) and makes the re-run update zero rows.
- **Migration test runs the real SQL.** The revision exposes `PUSH_DUE_DATES_SQL`; the test loads the revision module
  by path (precedent: `tests/models/test_opening_cache_audit_models.py::_load_migration_module`,
  `migration.MARK_CONFIRMED_SQL`) instead of mirroring SQL, so test and migration cannot drift.
- **New-items-due-immediately pin lives in the repository tests**, because item creation is in
  `compose_and_materialize_session` (`train_repository.py` ~2295), not in the pure scheduler.
- **Reversibility (D-05):** the data migration is `one-way` (pushed prod due dates cannot be restored after a downgrade).
  The owner already settled and accepted this in 244-CONTEXT D-05 ("harmless, items only resurface later"), so per the
  reversibility rules it keeps its rating and gets NO new `checkpoint:decision`; the plan stays autonomous.
