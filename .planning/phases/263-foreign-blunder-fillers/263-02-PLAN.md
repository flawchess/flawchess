<objective>
Client side of the warm-up retirement and of what the solver is told (D-04 client, D-10 to D-13): the copy library gets
the foreign tail line, the two welcome lines and the exhausted-day sentence; the session contract carries a derived
`own_puzzle_count` instead of the retired flag; every Train component that branched on the flag branches on
`own_puzzle_count === 0` or drops the branch.

Purpose: a session with no own puzzles is no longer a different kind of session, so the copy has to stay truthful
without a session name or the word warm-up.

Output: reworded `trainBotCopy.ts` with tests, the new contract field in `types/train.ts`, start screen, score screen,
solve screen, reveal and verdict details wired to it, every test fixture updated, a green lint/build/test/knip.

Wire contract this plan implements against (the backend side lands in 263-09): `TrainSessionResponse.own_puzzle_count:
number` = the session's own-game puzzle rows (all positions, solved or not), derived per response and never persisted;
`source` unions gain `'foreign_blunder'` and keep `'sharp_filler'` for cached verdicts and old solved results. Until
263-09 ships the field, a dev server omits it, `own_puzzle_count === 0` is false and the own-games copy shows, which is
the safe default.

Why a count and not the old flag (orchestrator ruling 8, recorded for the plan checker): Phase 206 D-04 rejected an
`sr_puzzle_count` field to avoid partial-shortfall notices. That is safe here because the persisted flag is gone (D-04),
D-12 and D-13 need the "no own puzzles" fact without a session flag (CONTEXT discretion: derive it), and the client only
ever reads it as `=== 0`, so no partial-count copy can arise.

Execution note: this phase runs in a single worktree, so same-wave plans execute sequentially, never in parallel.
</objective>
