<objective>
Client side of the foreign reveal (D-10, D-20, D-21): a solved foreign puzzle shows the move played in that game under
neutral labels and the game as neutral facts only, with no way to open the stranger's game.

Purpose: the reveal is where a foreign puzzle could leak its owner or claim the blunder as the solver's. Blunder
check's foreign footer (Phase 249 D-09) already solved the same problem; reuse it.

Wire contract implemented against (the server side lands in 263-06): `PuzzleRevealResponse.game_info?: GameInfo |
null` (the `GameInfo` type from `types/blunderCheck.ts`: time_control_str, time_control_bucket, played_at,
mover_rating), set only for a foreign puzzle; `game_id` is null for a foreign puzzle on `TrainPuzzle` and on the reveal;
the reveal's `played_in_game_san` / `played_in_game_move_uci` carry the owner's game move; `motif` is no longer sent.

Execution note: this phase runs in a single worktree, so same-wave plans execute sequentially, never in parallel.
</objective>
