<objective>
Make the single grading Worker safe for the instant-verdict overlap that plan 05 builds, and hand the
think-time key line over early. On the instant path the reveal opens before the phone's grade lands,
so the reveal's game-move search would today `stop` the in-flight anchor or after-played search and
drop its promise unsettled (RESEARCH Pitfall 1), losing both the late phone_grade record (D-12) and the
Your-move line (D-14). This plan queues that search behind the grading in one slot and adds the
`onKeyLine` callback plan 06 uses to render the solution card before the played search finishes.

Purpose: split out of the original plan 04 for context budget (checker scope_sanity); it is hook-only,
runs in wave 2 next to the backend plan 03, and lands before the instant branch exists, so the branch
never ships without the serialization.

Output: `gradingSettledRef` serialization, `GradeMoveOptions` / `onKeyLine`, hook tests incl. a
mutation proof.
</objective>

## Planning notes

- **Engine scheduling (discretion, RESEARCH Pitfall 1):** one queue slot, not a priority system. The
  free-play engine and the eval bar own separate Workers and cannot preempt grading; the walkthrough
  runs no engine. `gradingSettledRef` covers the WHOLE `gradeMoveInner` (anchor wait plus played
  search), so a fast mover whose anchor is still running is protected too. It resets on
  `startGrading`/`abortGrading`, because a superseded search never settles.
- **Why a separate plan:** the original plan 04 exceeded the smart-zone budget (110k). This hook-only
  slice has no file overlap with plan 03, so it runs in wave 2; plan 05 (the instant branch) proves the
  same serialization end to end through the component and re-runs its mutation there.
- **Tracer shape:** the hook is the only layer this plan touches, so the tracer is the thinnest path
  through it: grading in flight -> reveal search queued -> grading resolves -> reveal search resolves.
