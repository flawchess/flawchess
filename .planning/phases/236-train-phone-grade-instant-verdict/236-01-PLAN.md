<objective>
Server half of Part 1 of SEED-193: give every keyed Train solve a place to store the phone's own
1.5 s grading reading, so grading accuracy becomes a query instead of a Stockfish re-run. A new
nullable JSONB column `drill_solves.phone_grade` (D-01), a `PhoneGrade` boundary model mirroring
`SolveRecheck`, and the two write paths: the solve POST's claim UPDATE (D-13, phone-graded moves and
played == key) and the review route's coalesce write-once (D-12, the late reading for a
server-graded move that arrives after the instant POST). `move_quality` stays the effective tier
(D-02); the record is never a grading input.

Purpose: plan 02 (client) sends the record on the solve POST and plan 05 sends the late one on the
review flush. Old clients keep working (no record means SQL NULL, nothing else changes).

Output: one Alembic migration, a model column, the `PhoneGrade` and `ReviewRequest` schemas, the
two repository writes, the router wiring, a new schema test file, router tests.
</objective>

- **Spec-less probe fallback: skipped.** The phase has no requirement IDs to probe (ROADMAP:
  TBD); the CONTEXT decisions D-01..D-16 are the contract. Recorded here as a visible choice.
- **Review body shape (discretion):** a flat subclass `ReviewRequest(ReviewTelemetry)` adding one
  optional `phone_grade` field with a drop-invalid wrap validator. `ReviewTelemetry` itself is not
  edited (its schema and semantics stay intact, CONTEXT discretion note); pydantic inherits
  `extra="forbid"`, so an unknown top-level key still 422s.
- **Write-once on the review route (discretion):** `coalesce(phone_grade, <new>)` inside the SAME
  UPDATE that merges the telemetry, added to `.values()` only when a record arrived. Not a
  `phone_grade IS NULL` WHERE guard: that would make a second flush affect 0 rows, which the route
  reports as 404, and would drop that flush's telemetry (RESEARCH Pattern 5).
- **One column meaning (D-04):** the record is always the 1.5 s reading; the server cannot tell and
  does not check. Documented on the model and the schema so the audit query stays simple.
- **Privacy:** the record is engine numbers about the user's own already-stored move (same class as
  `recheck`, which shipped without a Privacy page entry); no new personal data, no Privacy copy change.
