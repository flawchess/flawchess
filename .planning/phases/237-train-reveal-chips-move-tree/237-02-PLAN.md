## Planning notes

- **Tree convention (Claude's discretion, research Pattern 1):** the hook's `mainLine` stays EMPTY (root seeded by
  `loadMainLine([], startFen)`); semantics come from derived `linePaths`. The list component later receives a VIEW
  (`listView.mainLine` = the active chip's path, `listView.nodes` filtered), so `VariationTree` renders the active line
  numbered with free sidelines inline and root forks before move 1 (sketch `selectedListHtml`).
- **Chip identity:** a chip's key is its primary role (`roles[0]`, canonical order your > best > game), so the key is
  stable as roles merge in late (a game move arriving later only appends a role).
- **Root-fork reachability (discretion):** free root forks stay in the tree and are listed as a sideline before move 1
  of the active line; with no chip active the list shows only the root forks (D-04).
- **Own-line sidelines (research Open Question 2, locked by orchestrator):** a chip tap while on a sideline that hangs
  off that chip's own line does NOT jump to the root.
- **Rewind with no focus (research A1, adopted):** rewinding to the root while no chip is focused restores the default
  You focus so the root always shows a lit arrow. Owner may flip this later; it is one line in `goToRoot`.
- **Divergent late lines:** in practice lines only ever EXTEND (best line = the key line, played line grows from the
  played move). If a line ever diverged, the stale continuation stays as a free branch; documented in a comment, no
  pruning code.
- **Keyboard wheel side effect:** passing the board ref to `useBoardNavigationInput` also enables wheel stepping over
  the board on desktop (Analysis parity). Accepted.
- **knip:** the new exports are imported only by tests until plan 04 wires them; knip's default (non-production) mode
  counts test-file imports, so this stays clean. If knip still reports them, stop and report; never add knip ignores.
- Spec-less probe fallback skipped this run (no requirement IDs).
