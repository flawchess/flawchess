## Assumptions recorded for the plan check

These are planner choices inside the CONTEXT "Claude's Discretion" area. The plan checker may challenge any of them.
A-2 and A-6 concern the client arbiter and are recorded in plan 255-02; A-1 (pass over locked steps) is withdrawn in
favour of owner decision D-23 (locked steps pause the route), delivered by plans 255-02 and 255-04 (A-7 there).

- **A-3 (step ID strings, rated costly):** the nine IDs are the RESEARCH Pattern 1 strings. They are stored per user
  and never renamed or reused; a new feature is a new ID (no re-minted keys, the old `train_bots_visited` mistake).
- **A-4:** a visit to a skipped step upgrades it to done (measurement nuance; the arbiter treats both as resolved). The
  DONE guard below allows it; the skip action itself arrives in plan 255-04.
- **A-5:** each stored step carries `with_dot` (was it current when resolved) for measuring the route in Postgres.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to `POST /api/users/me/feature-route` | untrusted action and step from any authenticated session, including stale tabs and old PWA bundles |
| browser to `GET /api/users/me/profile` | response now carries the caller's own route state |
| `users.prompt_state` JSONB | shared per-user object also holding `feedback_v1` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-255-01 | Elevation of Privilege | `feature_route_action` endpoint | high | mitigate | user id taken only from `current_active_user`; no user id in body or path; `FeatureRouteActionRequest` has `extra="forbid"` |
| T-255-02 | Tampering | `_DONE_SQL` in feature_route_repository | high | mitigate | step bound as `CAST(:step AS text)` (no string building); step restricted to the `FeatureRouteStepId` Literal, so arbitrary keys cannot bloat prompt_state; only the `feature_route` key is replaced, `feedback_v1` survives (Task 1 test) |
| T-255-03 | Repudiation | impersonated admin session, server side | medium | mitigate | `apply_feature_route_action` returns the read-only view when impersonation is set (Task 1 test); the client-side guard is T-255-14 in plan 255-02 |
| T-255-04 | Denial of Service | `build_feature_route_view` on profile GET | medium | mitigate | a stored value that fails validation is captured to Sentry with `set_context("feature_route", ...)` and returns `feature_route: null` instead of a 500; the write path rolls back |
| T-255-SC | Tampering | npm/pip/cargo installs | high | accept | no package is installed in this phase (RESEARCH Package Legitimacy Audit: none); any unplanned install is a deviation that needs the legitimacy gate and a blocking human checkpoint |
</threat_model>
