## Assumptions recorded for the plan check

These are planner choices inside the CONTEXT "Claude's Discretion" area. The plan checker may challenge any of them.
A-3, A-4 and A-5 (step ID strings, skipped-then-done, `with_dot`) are recorded in plan 255-01.

- **A-1 (under D-12, orchestrator decision 1, RESEARCH Open Question 1 RESOLVED):** the arbiter passes over a step
  whose target is locked (`requiresGames && !navUnlocked`): no dot, no `current` stamp, never marked. For the nine
  launch steps this equals "pause on the locked step", because the locked steps (Openings through Library Stats) are
  contiguous after Bots. It only differs for a games-free step appended after locked ones (for example the
  blunder-check step, D-09), which pass-over shows to a zero-game user and pause would hide. The Train step is never
  locked (D-21). Flagged to the owner.
- **A-2 (locked targets, D-15):** a visit to a step's page while its target is unavailable records nothing. `/openings`
  and `/endgames` sit behind `ImportRequiredRoute`, which renders a redirect to `/library/import` first, and the
  desktop logo links to `/openings`; without this gate a zero-game account would complete `openings` without ever
  seeing it. Library Stats without games is an empty page, treated the same way.
- **A-6 (orchestrator decision 6):** no new Umami events. Completions, skips, dates and `with_dot` live in Postgres;
  dot rendering is not a user action and frontend/CLAUDE.md forbids tracking from an effect on a value.
