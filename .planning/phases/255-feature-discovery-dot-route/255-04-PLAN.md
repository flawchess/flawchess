dot on it (D-10, D-11), and every account that exists at deploy starts with the launch route done (D-16, D-22) so the

get the whole onboarding route.

mutation's optimistic patch, and a data-only Alembic seed with its regression tests.

the D-01..D-22 audit.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-255-06 | Tampering | `_SKIP_SQL` | low | mitigate | the server recomputes active_days from user_activity and enforces `active_days >= since_days + FEATURE_ROUTE_SKIP_ACTIVE_DAYS` in the WHERE clause; a client can only affect its own route |
| T-255-07 | Tampering | `_CURRENT_SQL` | low | accept | a client may stamp current on any unresolved step of its own route; the worst case is its own dot order, and only the caller's row is reachable (T-255-01) |
| T-255-08 | Tampering | seed migration | high | mitigate | `||` adds only the `feature_route` key, the `WHERE prompt_state->'feature_route' IS NULL` guard makes it idempotent, the downgrade removes only that key; regression test pins `feedback_v1` survival and the validated shape |
| T-255-09 | Denial of Service | seed migration at container start | low | accept | one UPDATE over a small users table (thousands of rows, RESEARCH A2), sub-second |
| T-255-SC | Tampering | npm/pip/cargo installs | high | accept | no package is installed in this phase; any unplanned install needs the legitimacy gate and a blocking human checkpoint |
</threat_model>
