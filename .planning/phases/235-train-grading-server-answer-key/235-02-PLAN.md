<objective>
Anchor the phone's grading on the server key (SEED-192 step 2, D-01/D-07/D-08/D-09). The mount
search becomes an "anchor" search: with a usable key it evaluates the position after the key during
think time; without one (D-07) it is today's root search. `gradeMoveInner` then has one comparison
(anchor ES vs after-played ES), and `GradeResult.bestMoveUci` / `bestLine` / `esBefore` keep their
names and meanings for every downstream consumer, so the reveal arrow, line boxes, board badge and
free-play seed start naming the key with no further edits (RESEARCH Pattern 2).

Purpose: removes the user-28 contradiction (server says "only one move", arrow names the phone's
pick) and the mixed-horizon drop. Frontend-only plan with optional TS fields, so it runs in parallel
with plan 01 (no shared files) and stays correct against a server that does not send the key yet.

Output: `GradingAnchor`, `startGrading(fen, keyUci)`, `searchAfterMove` (terminal-aware), the
key-anchored grade and game-move search, the TrainPuzzle TS fields, tests.

## Planning notes

- **No server number in any drop (D-01):** the anchor ES is the phone's after-key search, never
  `graded_es_*` or a blob eval.
- **Mate-distance convention:** every displayed line is now an after-first-move search (key, played,
  game), so mate distances are consistent across the three boxes; the root-search "#N" of the old
  BEST MOVE box is not reproduced. Accepted, display only.
- **Terminal positions (bug fix inside this plan's scope):** the after-move search on a mated or
  stalemated FEN gets no usable score (Stockfish reports mate 0 or nothing), which today already
  mis-grades a non-best mating move and, with D-08, would mis-anchor every mate-in-one key. Scored
  directly instead (commented at the fix site).
- **Pitfall 6 (auto-queen):** an underpromotion key never equals the auto-queened played move; it
  goes through the search path. No special handling (scope).
