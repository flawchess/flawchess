<objective>
Teach the solve path the new grading facts (SEED-192 steps 2-3, server half): the sharp runner-up
is graded from the server's own blob (D-02), a confirmed phone disagreement on a sharp puzzle earns
the guess point for either guess after server sanity checks (D-14), and every re-check is stored in a
new `drill_solves.recheck` JSONB column so answer-key quality can be judged from prod solves
(D-17/D-18). The decision moves into one pure `_resolve_grade` so `record_solve` does not grow.

Purpose: plan 04's client sends the re-check and reads `SolveResponse.disagreement`; the Phase 230
leaderboards pick D-14 up automatically through `correct_guess`. Backend-only plan; old clients keep
working (no `recheck` -> today's grading, D-02 applies to them too).

Output: one Alembic migration, a model column, the `SolveRecheck` boundary model, `ServerGradedMove`
helpers, the resolver, the write, the response flag, tests.
