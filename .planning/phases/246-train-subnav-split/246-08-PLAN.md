<design_notes>
**A correction to RESEARCH Pattern 1.** It treats a mounted hidden landing as free. It is not, for anything that first mounts while hidden, because the one-shot effects then fire out of sight. `FeedbackAskBubble` POSTs a view on mount, and the third view auto-snoozes the ask (`FEEDBACK_ASK_MAX_VIEWS`). `useStreakArrival` reads and rewrites the last-seen snapshot, so the flame never ignites on the next real Today visit. Two routes reach this. Back out of a running loop first-mounts the whole landing while hidden, because the loop had unmounted it. Leaving Today before the session, settings or progress query resolves first-mounts those bodies inside an already-mounted panel. A first-mount latch on the panel covers only the first route, so `TrainStartScreen` takes `isVisible` and renders `TrainLandingHost` and `TrainStreakCard` only while it is true. `TrainScheduleSettings` stays mounted at a stable child position, which is all the debounce needs. Remounting on return replays nothing, because `resolveStreakArrival` returns `none` once the snapshot matches. The accepted costs on each Today return are one per-day-deduped view POST while the ask is active, and from plan 246-03 one leaderboard refetch from the rank line. `TrainReminderResurfaceBanner` stays mounted: its mount effect is a read-only device probe that records nothing.

**Tabs and the first-visit intro, checked in the code.** D-16 keeps the tabs visible during Tank's first-visit intro, and `isVisible` unmounts `TrainLandingHost`, so this plan states what happens. That landing bubble holds no local state: it picks Tank from `settings.intro_seen_at` through `landingHost`, so remounting shows the same copy and nothing restarts. The two-bubble stepper is a different thing: `introStep` is a `useState` inside `TrainSolveScreen` (`TrainSolveScreen.tsx:625`), which only renders in the immersive view, where the tabs are hidden. No tab can interrupt it. Browser Back can: the `isToday` gate from plan 246-02 unmounts the solve screen and the step is lost. `intro_seen_at` is stamped only on the closing step's guess (`handleIntroGuess`), whose comment says an abandoned stepper replays next time, so the next Start shows the first step again. That is the same outcome as leaving the page mid-intro today, and Task 1 pins it rather than changing it.
</design_notes>
