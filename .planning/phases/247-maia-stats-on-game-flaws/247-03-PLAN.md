<objective>
Make every reclassification path that runs without Maia keep the stored Maia data correct (D-09) and tell the
operator when the backfill needs to run (D-11).

Purpose: `_classify_and_fill_oracle` is the single choke point for the drain, atomic submit, `backfill_flaws.py
--oracle-gap` and `opening_cache_repair.py rederive`. Clearing the stamp there (after the 4-way diff/upsert) makes
the re-runnable backfill re-score any game whose flaw set or Stockfish best move may have moved. Survivor
preservation needs no diff/upsert change because the Maia keys are never in `flaw_record_to_row` (RESEARCH Q4);
this plan proves that with a mutation test. The `backfill_flaws.py` default branch is delete-then-insert and DOES
lose values (RESEARCH Pitfall 4), so it clears the stamp explicitly.
Output: stamp-clear helper, `_classify_and_fill_oracle` return value, script reminders, tests.
</objective>
