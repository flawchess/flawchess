<objective>
Create the blunder-check persistence (D-15), the backend beta gate (D-01) and every read path the session composer
needs: candidate game picks (own and foreign, D-09), the batch loaders, and the served sets for no-repeats (D-10).
The tracer proves the stack end to end with the start screen's first call, `GET /api/blunder-check/sessions/open`.

D-15 decision (planner, written down as CONTEXT asks): own tables, not shared session columns. `drill_sessions` has
schedule-bound NOT NULL `session_date`/`expires_on` (D-02 says blunder check is not tied to the schedule) and its
`uq_drill_sessions_user_open` index would stop a user from holding an open puzzle session and an open blunder-check
session at once. Phase 250's cross-mode needs (streak across modes, shared schedule, cooldown) read a UNION over both
session tables plus `blunder_check_windows (user_id, game_id, blunder_ply)`, so MVP rows never need a data migration.
Windows snapshot their start FEN and move list, so a foreign owner deleting a game (FK SET NULL) never breaks another
user's session (Pitfall 7) and no VOID outcome is needed.

gsd-executor run dies mid-plan (project memory: SSE "Connection closed mid-response" on long DB-heavy runs),
re-dispatch with "resume at the first task without a commit" or let the orchestrator run the remaining task inline;
never redo a committed task.

Purpose: plan 03 composes sessions on top of these loaders; plans 04-05 drive answers through these tables.
Output: models, migration, router skeleton with the beta gate, repository read/insert paths, shared test seed helper.
