<objective>
Make a beta user able to start a blunder-check session: `POST /api/blunder-check/sessions` draws 6 window shapes,
fills them from the user's own unserved fully evaluated games first and from similarly rated users' games when own
supply cannot fit a shape, snapshots each window, and persists the session (D-02, D-03, D-07, D-09..D-11, D-15).

Selection mechanics (Claude's discretion, recorded): on the fly per session start, game-first, Python judgements on the
classifier's own pass. Prod probe for the heaviest beta user: pick + positions about 240 ms warm, about 350-450 ms
with flaws and Python, inside the < 1 s target; the ix_games_user_full_evals index from plan 02 removes the cold heap
scan. A precomputed pool would need hooks into every eval write path and a backfill and would go stale on each retune.

Purpose: plan 04 drives answers on these windows.
Output: selection service, compose-or-resume service, POST endpoint, tests.
</objective>
