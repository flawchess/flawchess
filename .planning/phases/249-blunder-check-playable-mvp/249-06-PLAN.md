<interfaces>
Backend contract (plans 02 and 04; mirror field names exactly in frontend/src/types/blunderCheck.ts as string-literal unions):
- `GET /blunder-check/sessions/open` -> `BlunderCheckSessionResponse | null`
- `POST /blunder-check/sessions` -> `BlunderCheckSessionResponse` (409 detail "No blunder-check windows available")
  `{session_id, window_count, current_position: number | null, session_points, windows: {position, state: 'pending'|'active'|'ended', outcome: WindowOutcome | null, points_scored}[]}`
- `POST /blunder-check/sessions/{sid}/windows/{p}/start` -> `{position, start_fen, orientation: 'white'|'black', lead_in_ucis: string[], answered: AnsweredMove[], prompt: {move_index, move_uci}, timer_remaining_ms, move_timer_seconds, window_points, session_points}`
- `POST /blunder-check/sessions/{sid}/windows/{p}/answers` body `{move_index, answer: 'safe'|'blunder'|'timeout', client_elapsed_ms}` -> `{move_index, result, points_awarded, points_forfeited, window_points, session_points, window_ended, outcome, reply_uci, next_prompt, timer_remaining_ms, better_move: {fen, key_uci, server_graded_moves: {uci, tier}[]} | null}`; 409 detail "stale_prompt" means re-fetch the window via start
- `POST /blunder-check/sessions/{sid}/finish` -> `{session_id, session_points, points_possible, score_pct, windows: {position, outcome, points_scored, points_possible}[]}`
- `WindowOutcome = 'cleared'|'caught'|'missed'|'false_alarm'`; `AnswerResult = 'correct_safe'|'false_alarm'|'caught'|'missed'|'timeout_safe'|'timeout_blunder'`
Server timing (plan 04, D-18): the server stamps prompted_at when it issues a prompt (window start, or the previous
answer's response). `timer_remaining_ms` = 15 s minus the real time since prompted_at, clamped at 0: a resumed prompt
gets no extra time. Answers later than MOVE_TIMER_SECONDS + PROMPT_ANIMATION_ALLOWANCE_S (3) + NETWORK_GRACE_S (2) are
graded as timeouts. The 3 s allowance covers the client animation before a freshly shown prompt's countdown: the
lead-in replay after a window start, and the feedback display followed by the move and the reply after a correct
answer. Each of those must finish inside 3 s.
Existing frontend pieces: `useUserProfile` (hooks/useUserProfile.ts; `beta_enabled` is on the profile type),
`trainApi` style in api/client.ts, TanStack Query `useQuery`/`useMutation`, `Button` variants `default` / `brand-outline`.
Research (read these ranges only): 249-RESEARCH.md lines 285-294 (Q5 Frontend), 474-477 (Pattern 6 Timer), 550-552 (Pitfall 13).
