speaks one authored line in its own voice, in a bubble beside its avatar, on both
breakpoints, and the line clears on the player's next committed move. All of it lands as

depends on reading `lastRootPracticalScoreRef` before the grade continuation overwrites it
and on publishing it upward through a callback option; if that seam does not work, D-01's
"no extra engine calls" constraint has no implementation.

Output: the copy module with the first authored table, the pure trigger resolver with its
complete input interface, the bubble state machine hook, both engine seams, the
presentational bubble component, and a live game-start line on every persona game.

## Planning notes (recorded once, here)

- **Spec-less probe fallback skipped:** spec-less probe fallback skipped: phase has no
  pre-registered requirement IDs to probe (IDs are minted at plan time). The prohibition
  recall in section B was run in-prompt and its output is the `must_haves.prohibitions`
  block in each plan.
- **ROADMAP success criterion 3 is restated in D-01's terms.** The ROADMAP says "swing
  detection is WDL-based"; CONTEXT D-01 supersedes it with the existing post-bot-move
  Stockfish practical-score delta. The *intent* of the criterion is unchanged and still
  testable (an Attacker sacrifice must not trigger an apology), and the score-delta signal
  satisfies it for the same reason a WDL one would: a deliberate sacrifice that keeps the
  practical score flat produces no swing. BOTVOICE-03 is worded in D-01's terms. Flagged
  here so verify-phase does not read it as a scope drift.
- **`celebrationHold` only holds after a human WIN** (RESEARCH Pitfall 7,
  `useWinCelebrationHold.ts:24-28`). CONTEXT's discretion note assumed the hold applies to
  all three outcomes; it does not. Planner resolution (RESEARCH Open Question 1): ship the
  game-end line in the bubble unconditionally and change no timing. Accepted trade-off:
  on a loss or a draw the line is not read first, because `GameResultDialog` opens
  immediately. Extending the hold to losses and draws would change shipped behaviour and
  is out of scope.
- **`pb-20` stays on mobile** (RESEARCH Pitfall 5). CONTEXT's code-insight note says the
  bottom-nav clearance goes away once the bar is the page's own; it does not, because the
  replacement bar uses the same `MOBILE_BOTTOM_BAR_CLASSES` fixed positioning. The board
  width win for SC4 comes from deleting the two in-page 48px rows and the banner slot, and
  the 375x667 before/after measurement is a manual UAT step (plan 06).
- **`trainBubbleState.ts` lives in `frontend/src/components/train/`**, not in `lib/`.
  CONTEXT's code-insight note places it in `lib/`; the pattern it demonstrates is still
  the one `botLineTrigger.ts` copies.
- **The trigger key set is ten, not eleven.** The ROADMAP lists "the bot's own check or capture" as a separate trigger; CONTEXT's domain block folds it into the earned tease ("the bot's own check/capture that realized a big swing"), and D-03 confirms it ("delta is delta"). There is no standalone check-or-capture line.
- **`BotLineKey` is defined in `botGameCopy.ts`, not in `botLineTrigger.ts`.** The key IS
  the copy table key: `BOT_LINE_TABLES` is a `Record<BotLineKey, Record<PersonaId, string>>`,
  so a trigger key can never exist without authored copy for all 24 personas. The resolver
  imports the type. This also keeps the copy plan and the trigger plan on disjoint files.
- **The bubble slot is always rendered, at a fixed two-line height, even with no live
  line.** A collapsing slot would change the column's chrome height on every line, and
  `useFitBoardToViewport` would resize the board under the player. D-07's "fixed two-line
  height" is implemented as a reserved slot, not as a fixed height applied only while
  speaking.
- **A Custom game has no voice, with exactly one exception.** `BOT_LINE_TABLES` is keyed by
  `PersonaId` (D-08) and a Custom game has no persona, so `BotGameBubble` renders `null` for
  a null persona and the layouts simply have no bubble row. Fixed at game start, so no
  mid-game layout change. The exception is the bot's draw offer: it is shipped behaviour
  today via the banner D-12 retires, and a Custom game whose bot offers a draw must still be
  able to accept or decline. BOTVOICE-05 therefore gives the bubble a persona-less form that
  renders whenever action buttons are supplied, carrying the generic offer sentence preserved
  verbatim from the retired banner. No generic voice is introduced for any other trigger.
- **Package legitimacy:** no `npm install`, no `uv add` anywhere in this phase
  (223-RESEARCH.md "Package Legitimacy Audit: not applicable"). The `T-223-NN-SC` row in
  each plan's threat model is discharged by a lockfile-diff gate, not a per-package audit.
