<objective>
Run the prod refutation backfill, the catch-up and the coverage verification (D-11 steps 2-3), so at least 99% of
user-side blunders in fully evaluated prod games carry maia_refutation_prob, with the remainder explained by bucket.

EXECUTION MODE: ORCHESTRATOR-INLINE. Do NOT dispatch this plan to a gsd-executor subagent: the run takes about 8-10
hours, backgrounded children die with an agent, executor sessions time out around 40 minutes, and subagents cannot
call the flawchess-prod-db MCP server (project memory). The orchestrator launches the run detached and polls it.
Commits use plain `git commit` on main with the orchestrator's trailer lines; never the GSD commit helper; check
`git branch --show-current` prints main before every commit and push after each section so a same-day re-run never
overwrites an uncommitted report.

Purpose: D-11 makes the prod backfill and the >= 99% coverage part of the phase; plan 08's calibration needs it.
Output: committed shard reports and reports/maia-flaws-backfill/prod-refutation-coverage.md.
</objective>
