`apiClient` (a TanStack mutation), and on `pagehide` through a `fetch(..., { keepalive: true })` that

Analyze round trip by persisting the folded totals in the existing reveal cache (discretion).

2026-10-25 analysis derives "puzzle shown" from. Uses the route shipped in plan 01.

TrainSolveScreen, test mocks and tests.

## Accepted residuals (documented, not implemented)

- **Analyze, then never back to /train in that tab** (owner resolution 3): the component-scoped pagehide listener is gone, so no review flush lands. Identifiable as a solve patch without `review_*` keys.
- **In-app navigation away from a reveal** (e.g. a nav link to another page): a client-side route change fires no `pagehide`, so no flush lands. D-07 fixes `exit` to `next | pagehide`; capturing this would need an unmount flush with a third `exit` value, which is a change to a locked decision and is flagged to the owner instead of implemented.
- **Mobile app switch followed by the OS killing the page**: mobile browsers often fire `visibilitychange` (hidden) without a later `pagehide` before the kill, so the review flush can be lost. Inherent to D-03's pagehide trigger; flagged to the owner (a hidden-state flush is the usual remedy).
