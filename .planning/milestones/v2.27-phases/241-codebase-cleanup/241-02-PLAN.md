<interfaces>
CLI contract every later plan relies on (run from the checkout root; all paths repo-relative):

- Invocation: `uv run python .planning/phases/241-codebase-cleanup/tools/cleanup.py <command> [options] [paths...]`.
- Selection (all commands): `--scope FILE` (one path per line, `#` comments allowed; may be repeated) and/or positional files or directories. In-scope filter: `app/**/*.py` except app/prompts/ and app/data/; `tests/**/*.py` except tests/fixtures/; `frontend/src/**/*.{ts,tsx,js,jsx,css}` except frontend/src/generated/ and frontend/src/assets/. Anything else selected explicitly is an error (exit 2); directories silently skip out-of-scope files. The one opt-in for an out-of-scope file is `diff --outside PATH` (below).
- `scan [--gate] [--allow FILE ...] [--identifiers] [--advisory]`: prints `path:line:kind: text` for every tag match inside prose, kind ∈ comment, docstring, test-name, test-title (FE, 241-04), identifier (only with --identifiers). `--gate` exits 1 if any match is not allowed. Always allowed: the exact shape `(see SEED-NNN)` when `.planning/seeds/SEED-NNN-*.md` exists. `--advisory` also prints non-gating chronology hints (kind suffix `/advisory`).
- `apply-edits FILE.json`: list of objects {path, line, old, new}; `old` is the exact current text of `line` and the following lines it spans (joined by newline); `new` replaces them ("" deletes the lines; may hold several lines). All edits are validated before any write (all-or-nothing); applied bottom-up per file; refuses out-of-scope paths.
- `diff [--base SHA] [--allow FILE ...]`: for each selected file changed between base and the working tree (rename-aware), compares the code token streams; base defaults to tools/PHASE_BASE; prints residue as `path:line: - base_tokens / + head_tokens`; exit 1 on residue, parse error or directive mismatch.
- `diff ... --outside PATH` (repeatable; diff only): the explicit opt-in for a file outside the in-scope filter that a rename follows into (expected: scripts/tactic_tagger_report.py and scripts/benchmarks/chapter5.py for X4 in 241-67, .claude/skills/tactic-tagger-report/SKILL.md for X4, frontend/CLAUDE.md for the ScoreConfidenceTooltip rename in 241-61). A `.py` path gets the Python token diff above. Any other path gets the rename-only text check: the base blob and the working-tree file are each canonicalized by the applicable rename-map rows (whole-word old → new, canon_paths respected) and must then be byte-identical; residue prints as `path:line: - base_line / + head_line`. The path must be one file outside the in-scope filter (an in-scope path, a directory or a path missing on both sides is an error, exit 2); a file unchanged since base prints nothing and passes; allow lists apply as for any other file. Every other command rejects `--outside` (exit 2).
- `outside [--base SHA]`: prints every path changed between base and the working tree (from `git diff --name-status -M BASE`, both paths of a rename: committed and uncommitted changes to tracked files; untracked files are not listed) that the in-scope filter rejects, `.planning/` excluded, one per line, exit 0. It reuses the in-scope filter, so the filter has one definition; the final gate (241-70) compares this list with the out-of-scope files the rename plans name.
- `rows`: prints `INV-L<n> <A|M|B> <location> | <excerpt> | <replacement>` for every INVENTORY §6 row whose location file is selected.
- `ledger --ledger FILE`: exit 1 unless every selected §6 row has a line `INV-L<n>: <STATUS> <reason>` in FILE; STATUS ∈ APPLIED, MOVED, SKIPPED, LEFT, DEFERRED; every status except APPLIED needs a reason.
- `selftest`: built-in fixtures; exit 0 when all pass.
- Plugin hooks: for .ts/.tsx/.js/.jsx/.css files cleanup.py imports `tools/fe_support.py` (functions `prose(path, text)` and `tokens(path, text)`, same record shapes as the Python side) and exits 2 with "FE support is added by 241-04" if absent. If `tools/extras.py` exists, cleanup.py calls its `register(subparsers)` to add commands (241-03).
- Data files: rename maps `rename-maps/241-NN.tsv` (header `old	new	kind	absent_paths	ref	canon_paths`, kind ∈ identifier|file; `canon_paths` is an optional comma-separated list of repo paths the old → new canonicalization is limited to, empty or `*` = everywhere; generic names like `window`, `live`, `gc`, `full_hash` must be scoped); allow lists `allow/241-NN.tsv` (header `kind	path	needle	reason`, kind ∈ scan|diff|directive); ledgers `ledgers/241-NN.txt`. All under `.planning/phases/241-codebase-cleanup/`. Missing directories are fine.
- Allow auto-load: when `--scope .../scopes/241-NN.txt` or `--plan 241-NN` is given, scan and diff also load `allow/241-NN.tsv` if it exists (explicit `--allow` files add to it; an `--allow` file that does not exist is treated as empty). `--all-allow` loads every `allow/*.tsv` (used by the final gate).
