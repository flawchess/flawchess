<objective>
Server side of the warm-up retirement (D-04) plus the two deploy-time pieces orchestrator ruling 3 asks for (the
migration data step and the lazy completion on resume), and the one-way migration with its round-trip tests.

Purpose: the client already reads `own_puzzle_count` (263-02). This plan derives it, drops the frozen flag and its
column, and makes sure no session stays open because its last unsolved rows became unservable.

Why a derived count is acceptable (orchestrator ruling 8, recorded): Phase 206 D-04 rejected an `sr_puzzle_count`
field to avoid partial-shortfall notices; the persisted flag is gone now (D-04), D-12 and D-13 need the "no own
puzzles" fact without a session flag (CONTEXT discretion: derive it, do not reintroduce the flag under another name),
the value is stable across resume because rows never change source, and the client reads it only as `=== 0`.

Output: own_puzzle_count end to end, lazy completion, migration c4e6a8b0d375, `tests/test_phase_263_migration.py`
covering both phase migrations.
