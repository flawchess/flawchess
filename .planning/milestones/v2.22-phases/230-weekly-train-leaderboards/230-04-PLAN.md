## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to PUT /users/me/profile | authenticated caller writes its own profile fields |
| users.leaderboard_hidden to every leaderboard read | one user's flag decides what every other viewer receives |
| product to users (disclosure) | usernames gain a new, visible use next to training results |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-230-11 | Elevation of privilege / Tampering | PUT /users/me/profile | medium | mitigate | The route acts only on current_active_user.id (no user id in path or body); UserProfileUpdate gains only a bool or None field, beta_enabled stays unknown-and-ignored (existing mass-assignment test still runs); non-boolean input is a 422 (test) |
| T-230-12 | Repudiation / Information disclosure | Privacy page and default-visible model | medium | mitigate | D-06 owner decision keeps opt-out (visible by default); the Privacy page line ships in the same release as the boards and names the exact data shown and the way to hide it |
| T-230-13 | Information disclosure | stale board after hiding | low | mitigate | Visibility is enforced server-side on every leaderboard read (Plan 01); the mutation also invalidates the cached board; end-to-end router test proves other viewers lose the row |
| T-230-14 | Tampering | guest writing leaderboard_hidden via the API | low | accept | The card is not rendered for guests; a guest PUT is harmless because guests never appear on anyone's board regardless of the flag |
| T-230-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan (RESEARCH Package Legitimacy Audit: none); any unplanned install stops for a blocking human checkpoint |
