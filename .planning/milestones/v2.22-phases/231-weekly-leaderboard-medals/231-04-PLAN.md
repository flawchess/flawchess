<objective>
Celebrate medals: the first time a medallist opens Train after a week closes, a dialog lists every unclaimed medal; the Claim tap unlocks audio, plays the win chime, fires confetti and records the claim server-side (dismiss records it silently).

Purpose: the dialog is the moment that makes the deadline feel real (SEED-186 "Celebration"); the Claim button exists because browsers, and iOS in particular, only allow audio after a user gesture.
Output: wire types and API methods, the query/mutation hooks, dialog copy helpers, the medal-pop animation, the presentational MedalClaimDialog, the landing host, the TrainStartScreen mount, and tests (including the landing tests' new mocks).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/train/medals/claim | The browser posts the keys it was shown; the server scopes them to the caller (Plan 02) |
| admin impersonation session -> user's celebration state | An impersonating admin acts with the user's identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-231-16 | Repudiation / Tampering | admin impersonation consuming a user's celebration | medium | mitigate | Host disabled (no GET, no dialog, no POST) when profile.impersonation is not null; host test (Task 1) |
| T-231-17 | Tampering | duplicate claim POSTs (Claim + Radix close, remounts) | low | mitigate | Settled-ref guard in the dialog, per-mount closed state in the host, server idempotency (Plan 02 T-231-13); tests (Tasks 1-2) |
