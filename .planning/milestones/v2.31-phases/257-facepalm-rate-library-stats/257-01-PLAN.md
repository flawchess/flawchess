<objective>
Give every scored blunder a facepalm type (missed win or allowed loss), computed in SQL from the
model's material inputs, and prove it end to end on the Flaws card: the API carries
`facepalm_type` next to `facepalm_score` and the Facepalm chip is tinted by it. Then pin the
type's Python and SQL twins against each other, add the 0.7 stats cut as its own constant, and
teach the reader-test seed helper to produce both types.

Purpose: CONTEXT D-02 (the type rule), D-08 / D-09 (tint by type), D-01 (the stats cut that plans
04 and 05 count with). Every later plan of this phase reads `facepalm_type_expr` and
`FACEPALM_STATS_MIN`.

Output: the type twin in `app/services/facepalm_score.py`, `FACEPALM_STATS_MIN`,
`FlawListItem.facepalm_type` on both stacks, `FACEPALM_TYPE_STYLE`, a tinted `FacepalmChip`, a
typed seed option, and parity tests.

Intermediate state after this plan: only the Flaws-card chip is tinted. The analysis move-list
mini-chip and the eval-chart tooltip still use the neutral colours, and the chip popover does not
name the type yet; plan 02 puts the type on the flaw markers and plan 03 does those (D-10) and
deletes the neutral constants.
</objective>
