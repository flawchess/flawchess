## Decisions recorded by this plan

- **D-01 ship order.** Release 1 = the audit-table migration (CACHEFIX-01) + the repair
  script (CACHEFIX-02..07, CACHEFIX-10's `legacy-sample`) + CACHEFIX-12 as a plain upsert
  through the existing shared function + the backfill-SQL fix + the db-report checks. The
  two-source hardening (CACHEFIX-08) is Release 2 and ships only after the prod repair, so
  `confirmed` never has to lie about unscreened rows and prod never spends a multi-day
  window with opening dedup effectively off. Reversibility: **costly** — reversing the
  order later means either accepting that window or marking unscreened legacy rows
  `confirmed=true`.
- **The SIGTERM evidence is split in two** (RESEARCH §Testing SIGTERM-mid-batch resume): the
  automated gate is the in-process `CancelledError` injection already landed in plan 01
  (deterministic, runs under `-n auto`), and the literal `kill -TERM` lives here as an
  operator step. Both are required; neither substitutes for the other.
- **Dev has zero natural poison** (lichess cross-check on dev: 2,137 checked, 0 bad), so the
  smoke must inject a synthetic poisoned row or the `flagged -> confirmed_bad -> propagate
  -> rederive` chain is never exercised.

9. `... propagate --db dev`; assert one `opening_cache_repair_rows` row per carrier at `ply = n.ply - 1`, and that a second run rewrites zero rows.
10. `... rederive --db dev`; on one affected game assert blobs preserved on surviving flaws, `games.blobs_completed_at` cleared if a new flaw appeared, `drill_items` pruned only where the flaw is gone, `herring_pool` count unchanged, `drill_solves` count unchanged.
11. `... report --db dev`; confirm the file lands under `reports/opening-cache-repair/` and the verification block ran.
12. `... legacy-sample --db dev --n 20`; confirm one of the two `LEGACY-COHORT-DECISION:` lines printed.
13. Repeat step 6's `kill -TERM` for `confirm`, `propagate` and `rederive` (each must resume cleanly).
14. Reconcile: diff the cache row count against the step-2 snapshot; the only permitted difference is the orphan deletions step 7 reported. Investigate anything else before proceeding.

Never run `bin/reset_db.sh`. Never truncate the cache. Do not background any of these
