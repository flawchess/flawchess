<objective>
Close the two gate holes SEED-165 identified and give the missed orientation the same board
the allowed orientation gets.

Purpose: 11% of all allowed tags in prod — 78% of `sacrifice`, 47% of `clearance`, 23% of
`intermezzo` — fire in lines where the tagging side is LOSING, because the forcing-line gate
never checks that the solver is winning where the tactic fires. Separately the gate is
skipped outright whenever the pre-flaw position carries `eval_mate` instead of `eval_cp`, so
mate-adjacent flaws are ungated entirely. And the missed pass runs on a stackless board, so
cook's two move-stack predicates cannot fire there at all — dev shows 64 allowed intermezzo
tags against 2 missed (32x; prod 188 against 6).

Output: a per-tier winning floor at the firing node with a `game_positions` fallback, a gate
that always runs, and a missed pass whose board carries the opponent's previous move.
</objective>

## Planner decisions this plan locks

- **Open Question 2 resolved: `>=`.** The tier-1/2 floor credits a dead-equal firing node.
  Implemented exactly as D-01 words it (`cp >= floor`), with explicit boundary unit tests at
  0 / -1 and at 200 / 199 so the choice is visible rather than incidental.
- **D-02 read as "no ADDITIONAL node-0 check".** The floor is evaluated at the rounded
  firing index whatever it is, including 0 when a motif genuinely fires there. The
  alternative reading (never check index 0) would exempt hanging-piece entirely — 1192 dev
  allowed rows, 37 of them losing — which is not what D-01's 0-floor for tier-1/2 is for.
  Flagged so the developer can invert it with one guard.
- **D-03 fallback scope: `pv_blob is None` only.** `pv_blob == []` keeps its current
  skip-everything semantics verbatim, because D-04 states the `[]`-sentinel behaviour is
  unchanged and today that sentinel means "could not assemble, FINAL case, never
  suppressed". Recorded as a flagged interpretation in `221-01-PLAN.md`; plan 06's dev smoke
  reports the `[]` row count so the exposure is measurable.
- **No new parameter on `_classify_tactic_gated`.** Both new eval reads are derived inside
  it from the `positions` list all four callers already pass, so `_build_flaw_record`,
  `eval_remote.py`, `retag_flaws.py` and `ab_validate_gate.py` are untouched by this plan.
  Plan 03 has already made the retag's positions list carry `ply-1`, which is what makes
  this safe.
- **Unresolved edge carried forward.** TAGFIX-06's edge category came back `unclassified`
  from the deterministic probe. It stays `unresolved`, not dismissed. The planner's
  assumption is that the only edge worth pinning is the ply-0 / malformed-previous-SAN
  fallback, which the last `must_haves` truth and task 3's test cover. A second edge, if the
  developer sees one, belongs here.
