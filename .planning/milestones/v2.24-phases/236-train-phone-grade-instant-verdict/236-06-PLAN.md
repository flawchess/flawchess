## Planning notes

- **Loading visual (discretion):** reuse the existing `train-game-line-loading` markup (Loader2 plus
  "Loading…" at `text-sm`) inside the same Card shell; testid `${box.testid}-loading`. The failed card is
  the header alone (SAN, no eval) with `data-line-status="failed"` on the Card, no error copy (D-15).
- **One state object:** `InstantGradeState { status: 'pending' | 'failed'; keyUci; keyLine }` is the only
  new reveal input; `null` means "no instant grade outstanding" (today's path, or the grade landed).
- **Eval bar (RESEARCH Open Question 3, decided):** gate it while pending. The instant-path population
  is exactly where the server tier is free ground truth for phone accuracy; a concurrent eval-bar search
  on a phone would lower the background search's depth and bias that sample (A1, unmeasured). Cost: the
  bar appears up to ~1.5 s later on ~17% of solves; the verdict is not delayed.
- **Bubble (RESEARCH Open Question 2, decided):** a copy-less spinner (`submitting` state) for the POST
  round trip, so the user sees the move was taken without any "Checking your move…" copy (D-16).
- **Analyze during the background search (Open Question 4):** accepted known gap, documented in code.
- **Phase close:** last plan; the full pre-merge gate runs once here with plans 01-06 applied, plus one
  serial run of the train backend tests (memory: serial CI hides isolation bugs). No bin/reset_db.sh;
  plan 01 already migrated the dev DB. Do not background any command.
