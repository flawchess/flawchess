## Planning notes

- **Data flow:** chips are built ONCE in TrainSolveScreen (it already owns gradeResult, instantGrade, the played move,
  the qualities and the reported game move) and passed down; TrainReveal keeps the reveal GET and the game-move search
  and now reports the search's full `GameMoveLineState` up (needed for the game chip's loading/failed state).
- **TrainReveal keeps a slot** for the move list (`treeList: ReactNode`) so its unit tests stay presentational; the chips
  row is data-driven (`chips`, `activeChip`, `onChipSelect`).
- **Interim in this plan only:** piece drops still start the old free-play mode (seeded from `tree.currentPathUcis`), and
  Solution in the bubble returns the tree to the root and ends free play. Plan 06 removes free play; plan 07 replaces
  Solution with the bar's rewind.
- **Telemetry interim:** the v1 card counters are no longer fed (no cards); list taps still count as line steps. Plan 09
  switches the payload to v2 chips counters.
- **Assumption-delta scan** flagged "second mode"; this plan PROMOTES the tree to the single reveal model (the decision
  block lives in plan 06, which deletes the second mode).
- **Split from plan 04 (checker scope_sanity):** the components and their unit tests moved to plan 04. The swap, the
  card-era removal and the reveal test ports stay together here on purpose: rendering chips instead of cards breaks the
  card tests in TrainReveal / TrainSolveScreen / restoredGameArrow / solveLoop at once, so separating the ports would
  leave this plan with a red suite.
- **Heavy plan:** run test files individually while iterating, commit after each task, never background a test run.
- Spec-less probe fallback skipped this run (no requirement IDs).
