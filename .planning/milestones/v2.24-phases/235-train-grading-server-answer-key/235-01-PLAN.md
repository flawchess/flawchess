<objective>
Put the server's answer key on the pre-attempt Train payload for every source (SEED-192 step 1,
D-05/D-06/D-07/D-19). One pure derivation (`answer_key_for`) maps the data the server already owns
(SR: `game_positions.best_move` + the live `game_flaws.missed_pv_lines` blob; herring:
`herring_pool.ladder`; sharp filler: the CSV `solution_uci`) to `(key, puzzle_type, runner_up)`, a
python-chess legality check maps any bad key to null (D-07), and ONE session-scoped query attached at
the end of `compose_and_materialize_session` covers the fresh, resume and race-resume paths.

Purpose: the phone can only grade against the key (plan 02) and only decide the sharp re-check
before the POST (plan 04) if the key, the puzzle type and the sharp runner-up arrive before the
attempt. Plan 03 reuses `answer_key_for` at solve time so composition and solve can never derive the
key two different ways. Backend-only plan: an old SPA ignores the three new JSON keys.

Output: `TrainPuzzleType`, `PuzzleAnswerKey`, `answer_key_for`, `legal_answer_key` in
`app/services/train_pool.py`; the funnel in `app/repositories/train_repository.py`; three
`TrainPuzzle` fields; router mapping; tests.
</objective>
