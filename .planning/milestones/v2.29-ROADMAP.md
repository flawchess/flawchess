### Phase 244: Train SR Ladder Rework, Calculation Not Recall (SEED-207)

**Goal**: Make Train's spaced-repetition repeats test calculation instead of recall of the previous attempt or
the reveal screen. Prod evidence (SEED-207, ~9.6k SR solves): repeats after a fail are +14 pts accurate and
0.62x think time at day 1, back to the user's own baseline by day 3-4; a self-found solution stays remembered
for about a week and is gone by 8-11 days. Retry delays move past those windows. Locked decisions, evidence
tables and rejected options in SEED-207.

- **Ladder (`app/services/train_scheduler.py`):** correct solve (including the first attempt) -> retry in
  10 days (244-CONTEXT D-11, was 14 in SEED-207); wrong solve (any step) -> retry in 4 days, streak to 0; mastered after **2** consecutive correct
  (was 3). Named constants (`CORRECT_RETRY_DAYS`, `FAIL_RETRY_DAYS`, `MASTERY_STREAK_THRESHOLD`) replace
  `LADDER_DAYS`; no weekday snapping (244-CONTEXT D-02). Brand-new items stay due immediately
  (check the initial `due_date` path in `train_pool.py` / `train_repository.py`).
- **Parking:** Door A stays at 3 fails never solved; Door B (leech) `LEECH_FAIL_THRESHOLD` 6 -> 4 lifetime
  lapses. Docstrings and the Door B rationale in `train_scheduler.py` and `drill_item.py` updated.
- **In-flight migration (one-off, details in 244-CONTEXT):** no streak remap; due dates pushed
  to at least last correct solve + 10d / last fail + 4d (from `drill_solves`); no retroactive Door B parking;
  mastered/parked rows unchanged. No schema change.
- **Copy:** Home.tsx ladder explainer, `MASTERED_TAIL` in `trainBotCopy.ts`, `MASTERED_EXPLAINER` /
  `PARKED_EXPLAINER` in `TrainStatsCard.tsx`, plus any other Train copy naming three solves / 3 or 10 days.
- **Tests + changelog:** `tests/services/test_train_scheduler.py` (offsets, mastery at 2, Door B at 4, fail delay
  snaps to a scheduled weekday, new items due immediately); CHANGELOG `[Unreleased]`.
- **Out of scope:** A/B test (too few users, repeat accuracy biased by gap length); the ~1-month post-ship
  re-check of SEED-207 Tables 2/3; same-motif mastery check and fast-correct recall flag (own seeds).

### Phase 245: Analysis Contextual Explain Bar for Flaws (SEED-208)

**Goal**: Give every flaw on the Analysis page a one-click guided explanation, like chess.com Game Review's
Explain button, using the PVs FlawChess already stores. Today the better line and the refutation are reachable
only through tactic motif chips, and most flaws carry no motif. Locked decisions, chess.com observations and
reuse map in SEED-208.

- **One Explain button, no coach prose, no LLM.** No "Best" button (duplicates Explain on the user's own flaws);
  no "Next" button (`useFastForward` "Jump to next key moment" already does it).
- **Contextual bar:** under the move list on desktop, directly above the mobile footer on mobile (the footer is
  at its 5-column limit on a 360px phone). Shown only when the current node is a flaw ply or inside that flaw's
  Explain line.
- **Scope:** every mistake and blunder, both sides, with or without a tactic motif. Inaccuracies are out
  (no `game_flaws` row, tactic-lines 404s; 245-CONTEXT D-08). Null PV falls back to the other line, and the
  bar is hidden when neither exists (D-09/D-10).
- **Direction rule (same as the tactic motif badges):** user's own flaw opens the MISSED PV forking at ply-1;
  opponent's flaw opens the ALLOWED PV forking at the flaw ply.
- **Behaviour:** Explain grafts the line and plays its first move immediately; Back/Forward step through it
  (`goForward` already prefers the PV child); Explain becomes "Got it" while in the line, which closes it
  (`deleteSubtree`) and returns to the flaw move. Leaving the line any other way keeps it open, like tactic chips.
  Chip and Explain share the `flawKey(ply, orientation)` line key, so no duplicate sidelines.
- **Reuse, no backend change expected:** `GET /library/flaws/{game_id}/{ply}/tactic-lines` (`missed_moves` /
  `allowed_moves` for any `game_flaws` row), `handlePvChipClick`, `openLines`, the `pendingFlaw` graft effect,
  `findFocusedFlaw` / `focusedPvLine` in `pages/Analysis.tsx`.
- **Open for discuss/UI-SPEC:** bar visuals and copy (severity + move label?), icon, dark tokens, testids; Umami
  event names; null-PV / final-ply handling (hide vs disabled with tooltip); interaction with the tactic-chip
  deep-link auto-open (`tacticOrientationAtPly`).
- **Out of scope:** free-play / what-if moves graded live by `useLiveMoveFlaw` (no stored PV).

### Phase 246: Train Subnav Split, Today / Leaderboard / Archive (SEED-261106-gw8)

**Goal**: Split the single-column Train landing into three URL-routed tabs and turn the mastered and parked counts
into a browsable archive. Today users can see those puzzles only as numbers. Also the base for the later retry
feature (SEED-261106-q92) and a Stats tab. Locked decisions, traps and breadcrumbs in SEED-261106-gw8.

- **Tabs:** Today at `/train` (must keep working for reminders, PWA and nav), Leaderboard at `/train/leaderboard`
  (existing `TrainLeaderboardCard`), Archive at `/train/archive`. Archive keeps its name; statistics get a separate
  fourth Stats tab later. Desktop and mobile, following the Endgames/Openings `TabsList variant="brand"` pattern.
- **Today:** streak card with Start button and a new rank line ("#4 this week") linking to Leaderboard, plus the full
  schedule card (collapsible and collapsed summary removed; the completed state's "Next session" line stays). The
  Points today tile leaves with `TrainStatsCard` and needs a new home, probably the streak card.
- **Archive:** Mastered / Parked toggle with counts and the existing explainer popovers, replacing `TrainStatsCard`.
  20 per page via the existing `Pagination`, newest first, tab and page in the URL so browser back from Analysis
  returns to the same spot. No filters in v1.
- **Card:** new small `TrainPuzzleCard` on `LazyMiniBoard` (not `FlawCard`). Horizontal, board left, details and
  buttons right; one column on phones, two on desktop. Pre-mistake position with no arrows on both lists, Analyze via
  `buildGameAnalysisUrl(game_id, ply)`, space reserved for a later Retry button.
- **Backend:** one new list endpoint. No migration expected.
- **Traps to resolve in planning:**
  - `POST /train/sessions` (`useTrainSession`) and `useTrainGradingEngine` must move to the Today route behind a thin
    layout, or viewing Leaderboard/Archive creates a session and loads the engine.
  - Hide the subnav during solve, score and restored-reveal views (the phone board is sized to the viewport).
  - `TrainMedalDialogHost` moves to the layout so a Leaderboard deep link still shows medals.
  - Sort key: `drill_items` has no `mastered_at`/`parked_at`, so sort by latest `drill_solves.solved_at`; verify that
    status only changes on a solve across all write paths.
  - Count mismatch: `mastered_count`/`parked_count` don't join `game_flaws` and lazy eviction can drop a flaw row, so
    the list must tolerate a missing row or the counts must change.
  - Leaderboard and Archive need their own empty states (`TrainEmptyBody` only covers the landing).
  - New interactive elements need `data-testid`; the Mastered/Parked toggle needs an Umami event if not URL-routed.
- **Out of scope:** Retry (SEED-261106-q92), the Stats tab, archive filters. Never list active puzzles with an Analyze
  button: seeing the solution before the next review defeats spaced repetition.
