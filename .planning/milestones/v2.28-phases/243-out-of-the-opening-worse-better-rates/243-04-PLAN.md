per-TC rank status and percentiles (D-06), the game-weighted headline (D-07), the pooled 95% Wilson gate against the
game-weighted peer median (D-08), plus the per-TC list (D-10) and footer data (D-11) the popover needs.

## Decisions taken in this plan (assumptions from RESEARCH, resolved)

- **A3 adopted:** a TC that passes the floor but has no CDF cell (or no persisted percentile) is excluded from the
  headline and the gate like a below-floor TC; the gate needs that TC's p50. It is listed with its status.
- **A4 adopted for the footer:** the footer band is the game-weighted p25/p75 (same weights as D-07). The per-TC list
  carries rate, percentile and games only (D-10), no per-TC band.
- **A5 modified:** card status when nothing contributes is pending > unranked > below_floor (RESEARCH proposed
  pending > below_floor > unranked). "Not enough games to rank yet" would be false when some TC already has enough
  games and only awaits Stage B or a CDF cell.
- **A6 rejected:** the pending rule mirrors Endgames exactly (`rank_status` with `eval_dependent=True`), because
  CONTEXT says "below-floor and pending states work as on Endgames". `eval_pending` counts the TC's ranked games with
  pending entry evals (per TC, not per colour, as on Endgames).
- **Dev-clock exception:** like `/endgames/ranked-stats`, the window uses SQL `NOW()` so the on-read counts match the
  persisted Stage B basis; documented in the route docstring.
