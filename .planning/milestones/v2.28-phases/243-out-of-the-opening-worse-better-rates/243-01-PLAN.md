## Decisions taken in this plan (planner, recorded per the orchestrator notes)

- **ENUM alignment folded in (A8, orchestrator note 1):** `benchmark_metric` becomes TEXT + CHECK on both tables in
  this phase's migration, per the root CLAUDE.md rule "align existing columns with this when you touch them". Rated
  `costly`, not `one-way`: the downgrade recreates the ENUM and casts back, no external system reads the column, and
  the only data at stake are rows on the 12 dead TC-suffixed labels (added and superseded in the same PR, never
  written by the current path; dev has 0 such rows).
- **Legacy-label rows (A7):** the upgrade deletes rows whose metric is outside the 13 live ids before adding the
  CHECK, and logs the deleted count through the `alembic.runtime.migration` logger, so the deploy never fails on a
  dead label and the deletion is never silent. Owner pre-deploy check (not run by this phase): on prod,
  `SELECT metric::text, count(*) FROM user_benchmark_percentiles GROUP BY 1` and the same for `benchmark_cohort_cdf`
  through the `flawchess-prod-db` MCP; expect only the 11 live labels.
- **Storage shape (Claude's discretion):** a `color` column, not per-colour metric ids, so the CDF and the user rows
  share the same two ids (D-04).
- **Not touched:** the native `time_control_bucket` ENUM inside the widened PK is shared with `games` (a huge table);
  converting it is out of scope and stays flagged, not silently changed.
- **A1 (sub-800 drop):** adopted. `fetch_sweep.py` (the design-note measurement) drops `ueag < ELO_FLOOR`, and the
  raw-rate builders drop sub-800 games, so the builder does the same.
- **A9 (phase coverage):** a game with no phase = 1 ply is treated as ended before the middlegame, exactly as
  `fetch_sweep.py` does. Phase is populated at import and was backfilled once; dev probe: 0 of 162,291 games have an
  all-NULL phase.
