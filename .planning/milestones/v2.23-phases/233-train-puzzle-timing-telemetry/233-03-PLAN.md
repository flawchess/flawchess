<objective>
Measure review time on the reveal and flush it so that no exit is lost (D-03): on Next through the
normal `apiClient` (a TanStack mutation), and on EVERY non-Next exit (screen unmount, which covers
in-app route changes and the Analyze link; the page turning hidden; `pagehide`) through one
`fetch(..., { keepalive: true })` helper that carries the Bearer token (D-06). Every flush carries
`exit` (D-07), with `"pagehide"` meaning "left the reveal without pressing Next". Keep one review timer
across the Analyze round trip by persisting the exact flushed totals in the existing reveal cache
(discretion).

Purpose: review time is SEED-190's "learning effort" signal, and `exit` is the abandon signal the
2026-10-25 analysis derives "puzzle shown" from, so an abandon that sends nothing biases both. Uses the
route shipped in plan 01.

Output: review part of the hook (Next flush, one non-Next flush helper with three triggers, Analyze
snapshot), two client functions, an optional cache field plus an update-only cache helper, a few
wiring lines in TrainSolveScreen, test mocks and tests.
</objective>

## Accepted residuals (documented, not implemented)

- **A page killed with no lifecycle event at all**: if the browser crashes, or the OS kills a page that was never hidden first, neither `visibilitychange` (hidden) nor `pagehide` fires and the screen never unmounts, so no review flush lands. Nothing in a browser can observe this. Identifiable as a solve patch without `review_*` keys. (Mobile app switches DO fire `visibilitychange` hidden before a later kill, so they are covered by trigger (b).)
- **Fire-and-forget transport**: a keepalive request the browser drops (offline, keepalive quota, abort during unload) is lost and not retried. A 5xx response is reported to Sentry; rejections and 4xx are not (expected).
- **Out-of-order arrival**: a non-Next keepalive flush that is still in flight when the user returns and presses Next could, in principle, land after the Next flush and leave `exit = 'pagehide'` with the earlier totals. It needs a return-and-Next faster than the earlier request's network latency; accepted (T-233-20).
- **Modifier-click on Analyze** (new tab) is not an exit: the reveal stays open in the original tab and is flushed by that tab's own later exit (Next or a non-Next trigger).

Withdrawn from the previous revision (now covered by Task 2/3): Analyze-then-never-return (covered by the unmount flush), in-app navigation away from a reveal (unmount flush), mobile hide-then-kill (visibilitychange-hidden flush).
