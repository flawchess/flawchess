## Wire contract (the frontend plans consume exactly these names)

- `TrainModeState = Literal["pending", "in_progress", "done", "off"]`
- `TrainModeProgress`: `size: int`, `state: TrainModeState`, `remaining: int`, `pending: int`, `first_session_done: bool`
- `TrainBlunderCheckModeProgress(TrainModeProgress)`: `points_today: int`, `has_rated_games: bool`, `needs_level: bool`
- `TrainModesProgress`: `puzzles: TrainModeProgress`, `blunder_check: TrainBlunderCheckModeProgress`
- `TrainProgressResponse` adds `modes: TrainModesProgress`, `day_complete: bool`, `pending_count: int`,
  `blunder_check_notice: bool`
- `POST /train/blunder-check-notice/dismiss` -> 204

## State rules

- Puzzles: size 0 -> off; a completed session in window (`completed_session_in_window`) -> done; an open unexpired
  session with at least one solve -> in_progress; else pending. `remaining` = the existing `waiting_count`; `pending` =
  `waiting_count` when `badge_visible`, else 0 (unchanged badge semantics).
- Blunder check: size 0 -> off; a completed session in window -> done (`points_today` = its summed points_scored,
  remaining 0); an open unexpired session (rows with expires_on <= today are treated as absent, read-only like the waiting
  count) -> in_progress when any window was started, else pending, remaining = window_count minus ended windows; no
  session -> pending, remaining = size. `pending` = remaining when today is scheduled or an open unexpired session
  exists, else 0 (D-13).
- `day_complete` = `day_complete_on(today)` (plan 12). `pending_count` = puzzles.pending + blunder_check.pending.
