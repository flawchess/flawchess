**Frontend facts (TanStack query-core 5.108.3, axios 1.21.1):**

- `retry(failureCount, error)` gets 0 on the first failure, so `failureCount < 2` means at most 2 retries (3 requests). The default `retryDelay` is 1 s then 2 s; keep it.
- `MutationCache.onError` runs once, after the last attempt, so a recovered retry sends nothing to Sentry.
- Default `networkMode` ('online'): a retry that finds the device offline pauses, stays `pending`, and resumes on reconnect. In any mode a retry also waits while the tab is hidden.
- A hook-level `retry` beats a test client's `mutations: { retry: false }`, but the hook sets no `retryDelay`, so a test client with `mutations: { retryDelay: 0 }` makes retries immediate. No fake timers needed.
- No existing test rejects these two mutations with an axios ERR_NETWORK (they reject with plain `Error`), so none needs to change for the retry.
- A query with no data goes back to status 'pending' while a refetch is in flight, and returns to 'error' when it fails. The interval is recomputed on every state change and an in-flight fetch is never duplicated, so checking `status === 'error'` is enough.
