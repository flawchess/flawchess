## What changed

- `retryOnNetworkError` (frontend/src/lib/networkRetry.ts): true only for `AxiosError.ERR_NETWORK` and `failureCount < MAX_NETWORK_RETRIES (2)`. Set as `retry` on `sessionMutation` and `solveMutation` only; blunder-check mutations untouched. Default retryDelay (1 s, 2 s) kept. `solveMutation` has `networkMode: 'always'` so offline it settles to the existing "Couldn't save your result." row; `sessionMutation` keeps the default mode so an offline retry pauses and resumes on reconnect.
- `TrainStartScreen` gets a required `onRetry` prop and a `btn-train-session-retry` Retry button in the error state; `Train.tsx` wires `onRetry={loop.requestSessionReread}`.
- `withErrorBackoff` (frontend/src/lib/pollBackoff.ts): `false` stays `false`; otherwise the larger of the scheduled interval and 30 s while status is `error`. Both hooks compute their existing interval first (moved to module-level `scheduleEvalCoveragePoll` / `scheduleReadinessPoll`, logic unchanged) and wrap it.
- `normalize_chesscom_game`: silent `return None` for exactly aborted/aborted via `_CHESSCOM_ABORTED_RESULT`; every other unrecognized pair still captures to Sentry once.
- CHANGELOG bullet under Unreleased / Fixed for Task 1 only.
