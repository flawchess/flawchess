# Quick 260928-85v: Move Maia score_move off the API event loop

`score_move` (Maia-3 ONNX inference, ~150 ms/call, 6-13 calls per game) runs
synchronously on the event loop inside the async submit path:
`_build_best_move_candidates` (async) -> `_assemble_candidate_rows` (sync) -> `score_move`.
Every other request on the API process stalls while it runs.

## Task 1: Offload row assembly to a worker thread

- files: `app/services/eval_apply.py`
- action: in `_build_best_move_candidates`, call `_assemble_candidate_rows` via
  `await asyncio.to_thread(...)`. One thread hop per game (not per Maia call). The helper
  is pure (no session, no shared mutable state; the targets' boards are not touched by
  anything else while the coroutine awaits). onnxruntime releases the GIL and
  `InferenceSession.run` is thread-safe for concurrent calls. Comment the fix site.
- thread pool: default executor is `min(32, cpu + 4)` workers; the only other user is
  `guest_service` password hashing. No custom executor needed.
- done: behavior unchanged, existing candidate tests pass.

## Task 2: Test that Maia runs off the loop thread

- files: `tests/services/test_eval_apply.py`
- action: monkeypatch `score_move` to record `threading.get_ident()`, assert it differs
  from the loop thread's ident and the row is still produced. Prove the test by reverting
  the fix and confirming it fails.
- verify: `uv run pytest tests/services/test_eval_apply.py`
