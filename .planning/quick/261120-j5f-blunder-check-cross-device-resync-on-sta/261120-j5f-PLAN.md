# Quick 261120-j5f: Blunder check cross-device resync

Blunder check ends on the generic error screen when the same session is continued on a
second device (Sentry FLAWCHESS-DJ). Planned and executed inline by the orchestrator in a
dedicated worktree, because the main checkout carried in-flight phase 257 work.

## Root cause

`nextWindow` in `frontend/src/lib/blunderCheckDrill.ts` computes the next window as
`position + 1`. A device left on a window's solution asks for a window another device has
already played; the server answers 409 `window_ended` (correctly), and `useWindowLoader`
turns every start failure into the error phase.

## Task 1: resync from the server on a session-moved 409

- files: `frontend/src/lib/blunderCheckDrill.ts`, `frontend/src/hooks/useBlunderCheckSession.ts`,
  `frontend/src/components/train/blunder-check/BlunderCheckDrill.tsx`,
  `frontend/src/components/train/blunder-check/BlunderCheckTab.tsx`
- action: add a `SESSION_RESYNCED` reducer event; on a 409 `window_ended` or
  `previous_window_open` from start, begin or answer, re-fetch `GET /blunder-check/sessions/open`
  and jump to the server's `current_position` (finishing when it is null). On `session_closed`,
  or when the open session is missing or a different one, reset and return to Today. Other
  failures keep the error screen. Keep the `stale_prompt` path.
- verify: `npx vitest run src/components/train/blunder-check src/lib/__tests__/blunderCheckDrill.test.ts`

## Task 2: keep the handled 409s out of Sentry

- files: `frontend/src/lib/queryClient.ts`, `frontend/src/hooks/useBlunderCheckSession.ts`
- action: a mutation may declare `meta.expectedConflictDetails`; the global mutation error
  handler skips a 409 whose `detail` is declared. The start, begin and answer mutations declare
  the four details the drill recovers from.
- verify: `npx vitest run src/lib/__tests__/queryClient.test.ts`
