<objective>
Add a settings toggle that makes the analysis board's Jump (fast-forward) button stop only on the user's own key moments (blunders, mistakes, gem and great moves) instead of both players'. Default off, which keeps today's both-sides behavior.

Purpose: the Jump button currently stops on both sides on purpose (see the fastForwardStopPlies comment in Analysis.tsx). Users reviewing their own play want to skip past the opponent's errors and gems. The board keeps showing every highlight; only the Jump stop set changes.

Output: a pure, tested stop-set helper; a localStorage-backed preference in the existing display-settings store; the Analysis page wired to both; a Jump button switch in the shared SettingsPanel; a CHANGELOG bullet.

Scope decisions (planner discretion, no CONTEXT.md for this quick task):
- Storage is client-side localStorage in lib/engineSettings.ts, the same store as the engine line/arrow counts and engine on/off switches (useSyncExternalStore, flat non-email-scoped key so guests persist too). No backend column, no migration.
- "Your moves" means the plies of the game's user_color side (isUserPly). That is the side the board already orients to and labels as "you" everywhere else (badges, "Your opponent found a gem move!"). For a cross-user game opened by URL, that is the game owner's side, consistent with the rest of the board; the frontend has no viewer-ownership field, so no new ownership logic is added.
- Unknown user color falls back to stopping on both sides. Jump only runs in ?game_id= game mode (isGameMode), so pasted PGNs and free play never reach the filter.
- The setting is a panel setting, so Reset to defaults covers it (unlike the three engine on/off switches, which Reset deliberately leaves alone).
</objective>
