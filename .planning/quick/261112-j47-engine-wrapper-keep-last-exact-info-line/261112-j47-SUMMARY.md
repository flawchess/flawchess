# Phase quick-261112-j47 Plan 01: Engine wrapper keeps the last exact info line Summary

`EnginePool._acquire_and_analyse` now reads the raw Stockfish info stream and returns the last exact line per multipv index, so a trailing aspiration-window lowerbound/upperbound line (1-2 ply pv) can no longer overwrite depth, score and pv; old worker builds (schema <= 2) are gated off the three 1M-node lease lanes.

## What was done

1. **Engine wrapper (SEED-261112-s4v A1).** Added `_select_final_infos` (pure, per-index: last exact pv line, else last bound line, else last score-only line; pv-less `string`/currmove lines ignored; raw line objects returned, never merged) and `_collect_analysis_infos` (streams `protocol.analysis` inside `with analysis:` so cancel sends UCI stop). `_acquire_and_analyse` keeps its early returns, timeout branch (no restart), crash branch (Sentry + restart) and slot release; return shape unchanged. Bug-fix comment explains the dict.update merge and why `analysis.multipv`/`analysis.info` are not used either (a `lowerbound: True` key never gets removed).
2. **Version gate (A2).** `WORKER_SCHEMA_VERSION_MIN` 2 -> 3; `/flaw-blob-lease` and `/bestmove-lease` gain the `worker_schema_version` query param (default 1) with the gate as the first statement; worker `WORKER_SCHEMA_VERSION` 2 -> 3 and sends it on all four 1M-node lease calls (entry-lease stays param-less).
3. **Docs.** `REMOTE_WORKER.md` paragraph in "Updating the worker" ("older than ... schema version 3"); CHANGELOG `### Fixed` bullet under `[Unreleased]`.
