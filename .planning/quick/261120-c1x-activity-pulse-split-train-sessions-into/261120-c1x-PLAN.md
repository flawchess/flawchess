<objective>
Rework the Activity Pulse "Train sessions" section (superuser page at /activity) into two clearly separated mode blocks, Personalized Puzzles and Blunder Check (D-01). Add Blunder Check statistics: sessions by outcome, windows judged per day, 7-day rolling score % and a daily outcome mix. Replace the misleading stored-status "Still open" reading with a query-time derivation of three outcomes, Completed / Open / Abandoned (D-02, D-03), that leaves out puzzle sessions nobody started. Remove the guest Train note and its query (D-04).

Purpose: in prod, 331 puzzle rows are stored 'open' with expires_on already past, against 5 that are really open. Expiry is lazy: both `expire_stale_sessions` functions (app/repositories/train_repository.py and app/repositories/blunder_check_repository.py) flip open -> expired only when the same user next composes a session. A user who never returns keeps an 'open' row forever. 230 of those 331 rows were never started, because /train composes and persists a drill_sessions row on page mount. The dashboard currently charts all of them as live sessions.

Output: reworked queries, payload and tests (Task 1); reworked page shell, render layer, types and styles (Task 2); layout-harness fixtures, a DOM-id seam test, docs and changelog (Task 3).

Decision IDs used below (from the locked decisions in the planning context): D-01 = two mode blocks and the card trio; D-02 = fix at query time only, read-only, root cause documented; D-03 = Completed / Open / Abandoned with never-started puzzle rows excluded and the reference-date rule; D-04 = remove the guest note and the guest-Train payload field.

Shape note: this plan uses layer tasks (backend, frontend, harness/docs) rather than a tracer-first slice. The architecture is already proven: 17 existing cards follow the same SQL -> Payload -> render.js-by-id pattern. The orchestrator suggested this seam, and splitting by layer means each large file (activity_queries.py at 900 lines, the 1427-line test file, ActivityPage.tsx, render.js) is read once.
