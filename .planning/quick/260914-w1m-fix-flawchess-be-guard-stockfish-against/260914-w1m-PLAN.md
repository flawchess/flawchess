# Quick task 260914-w1m: guard Stockfish against impossible custom-position boards

## Problem

Sentry FLAWCHESS-BE (2026-09-13, two events, same trace): `EngineTerminatedError: engine
process died unexpectedly (exit code: -6)` from `EnginePool._acquire_and_analyse`. Both crash
boards are impossible positions (10 and 15 white pawns). They come from chess.com
custom-position games whose `[SetUp "1"][FEN ...]` root has more than 8 pawns per side (e.g.
two full ranks of white pawns). Prod has 12 such games (users 10, 11, 397). Nothing in the eval
pipeline checks `Board.is_valid()`, so every ply of such a game is fed to Stockfish, which dies
(SIGABRT in prod, SIGSEGV locally) on some of them and returns garbage on the rest.

Reproduced locally: `chess.Board('rnbqkbnr/pppppppp/8/8/8/PPPPPPPP/PPPPPPPP/RNBQKBNR w KQkq - 0 1')`
kills the vendored Stockfish with exit -11.

## Tasks

1. **Engine-pool guard** — `app/services/engine.py` `_acquire_and_analyse`: return `None` before
   taking a worker slot when `not board.is_valid()`. Protects every caller (drain, blob PV walks,
   scripts). Bug-fix comment at the site. Test: mocked protocol is never called for an invalid board.
2. **Target-collection exclusion** — `app/services/eval_apply.py` `_collect_full_ply_targets`:
   return `[]` when the PGN root board is invalid. This is the single choke point for the local
   full drain, the tier-4b bestmove lane, the remote atomic lease/submit and
   `scripts/opening_cache_repair.py`. With no targets the local drain stamps the game complete
   through the existing no-holes path, so it leaves the eval lottery instead of being re-picked.
   Test: an invalid-root PGN yields no targets; a valid custom-root PGN still yields targets.
3. **Changelog** — bullet under `## [Unreleased]` / `### Fixed`.
