<objective>
Stop the two frontend Stockfish hooks from letting a trailing lowerbound/upperbound info line (1-2 move PV, bound score) replace an exact line's moves. This is SEED-261112-s4v Part A item 4. The rule below is locked by the orchestrator (revised after the first plan review):

1. `useStockfishEngine`, per MultiPV rank:
   - (a) No exact line yet on the rank (empty or bound-only): accept the bound line as-is (first paint is not delayed).
   - (b) The rank has an exact line and the bound line's first move EQUALS that exact line's first move: overlay the bound line's score and depth live, and keep the exact moves.
   - (c) The rank has an exact line and the bound line's first move DIFFERS (a new move failing high): ignore the bound line for display, both live and final. The last completed iteration stays shown. Accepted consequence: the shown best move can lag Stockfish's `bestmove` by one unfinished iteration, the same choice as the backend fix 261112-j47.
   - (d) Final commit at a non-stale `bestmove`: per rank, restore the last exact line's moves, score and depth when one exists.
   - (e) If at least one bound line was overlaid or ignored on a rank holding an exact line during this search (case b or c), run the existing `dedupePvLinesByFirstMove` over the final snapshot. Otherwise do not dedupe, so exact-only searches behave exactly as today.
   - Exact lines always replace their rank, as today.
2. `useStockfishGradingEngine`: a bound line never overwrites a move's exact cache entry. It is stored only when the move has no entry or only a bound entry. Grading evals feed move classification and gem detection, so there is no live bound-score update here.

Purpose: the owner sees 1-2 move Stockfish lines on the analysis board and on the puzzle and blunder-check solution screens. Those are live WASM output, not stored data. The backend fix (quick task 261112-j47) already keeps the last exact line, and `useTrainGradingEngine` plus the worker pool already filter on exact. This plan brings the last two frontend hooks in line.

Output: two hook edits with bug-fix comments, extended tests in the two existing test files, a CHANGELOG bullet and the seed status note.
</objective>
