## Verified code facts (read in this worktree at 6cc81e165; line numbers approximate)

- `app/services/eval_apply.py` `_fetch_dedup_evals` (~341): the ONLY read of the cache for both lanes, filtered to
  `confirmed IS TRUE`, returns `{full_hash: (eval_cp, eval_mate, best_move, pv)}` with the raw pv. Its only pv
  consumers are `_fetch_cached_opening_hashes` (lease omission, keeps hashes whose pv is not None) and
  `_merge_dedup_pv_into_engine_map` (transplant), both in `app/routers/eval_remote.py`. `_resolve_full_eval` and the
  helper at ~1529 drop the pv element. The pv string is space-joined UCI (`_pv_to_uci_string` in
  `app/services/engine.py`, capped at 12, None when empty).
- `_merge_dedup_pv_into_engine_map` (eval_remote ~271) inserts the WHOLE cached tuple for opening plies the worker did
  not evaluate, also when pv is None. This matters: `_derive_atomic_sentinel_lines` rebuilds evals from
  `engine_result_map` with an EMPTY dedup map, so the merge must keep inserting `(cp, mate, best_move, None)` for an
  unusable pv. Skipping the merge would lose the eval for sentinel derivation and best-move candidates.
- Atomic submit (`_apply_atomic_submit`, eval_remote ~1409): `cache_targets` require `t.ply in worker_evaluated_plies`
  AND `t.full_hash not in dedup_map` (added in b75c17172, Phase 220). Every confirmed row is in dedup_map, so a
  worker's fresh pv for a confirmed row never reaches `_upsert_opening_cache`: the documented NULL-pv heal of a
  confirmed row is unreachable in this lane today (only a race between the two reads can hit it).
- Local drain (`_full_drain_tick`, eval_drain ~1403-1567): `engine_targets` exclude every dedup hit; the local drain
  never transplants a cached pv into a game. `_fill_engine_game_flaw_pvs` / `_missing_flaw_pv_targets` (~919-1020)
  re-search every dedup-transplanted flaw ply (N and N+1) because `engine_result_map` never holds those plies; they do
  NOT key on the cached pv being NULL, so no predicate change is needed there. Their results are merged into
  `engine_result_map` but `engine_targets_for_cache=engine_targets` (the pre-recovery list) means they never reach the
  cache: the heal is unreachable in this lane too.
- `_partition_cache_writes` (eval_drain ~583): confirmed or same-source row goes to `skip_pv_heal` only when
  `existing.pv is None and pv is not None`; unconfirmed different-source rows are promoted (kept pv = longer by string
  length) or replaced wholesale. `_heal_cache_pv` (~721) guards its UPDATE with a NULL-only WHERE clause.
  `_upsert_opening_cache` (~854) collapses same-hash rows in one batch, preferring a pv-bearing row.
- Benchmark lane flags (checked for separate cache paths, none found): `EVAL_AUTO_DRAIN_ENABLED` only gates claims
  feeding `_full_drain_tick` and the lease lanes; `BEST_MOVE_BACKFILL_ENABLED` gates the tier-4b lanes, which never
  touch `opening_position_eval`; `BENCHMARK_SELECTION_GATE_ENABLED` only narrows claim SQL;
  `BENCHMARK_HOMOGENIZE_EVAL_SOURCE` makes `derive_is_lichess_eval_game` False so lichess-arm games use the SAME
  `_fetch_dedup_evals` / merge / `_upsert_opening_cache` calls as engine games (their lease bypasses the redundancy
  filter via `stored_eval_predates_engine`, so every position is leased anyway). The tier-4 claim (SEED-202) also
  drains through `_full_drain_tick`.
