# Phase quick-261112-k56 Plan 01: Opening cache treats 1-2 ply cached lines as missing Summary

A truncated (1-2 ply) or NULL cached opening pv is now "missing" everywhere: the remote lease searches the position again, it is never transplanted into a game, and a strictly longer fresh pv heals the cache row in both the atomic-submit lane and the local drain, while eval_cp, eval_mate, best_move and the confirmation columns stay immutable.

## Scope finding (approved by orchestrator)

The documented NULL-pv heal of a confirmed row was unreachable in both lanes: the atomic lane excluded every dedup hit from `cache_targets`, and the local drain discarded its PV-recovery results (`engine_targets_for_cache=engine_targets` is the pre-recovery list). Both are now wired through the existing `_partition_cache_writes`, so a confirmed row can only take the heal bucket (never promote or replace). Side effect, accepted: confirmed NULL-pv rows now heal too. The local drain heals only flaw-ply positions (the PV-recovery predicate already re-searches every dedup-transplanted flaw ply, so no predicate change); the remote lane heals the rest through the lease.
