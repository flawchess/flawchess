- chess.js is 1.4.0. `frontend/node_modules/chess.js/dist/esm/chess.js`: `isThreefoldRepetition` (~2330) reads `_positionCount` for the current hash; `isDraw`/`isGameOver` (~2336-2344); `undo`/`_undoMove` (~2675-2700) restore turn, castling, ep square, halfmove, fullmove and decrement the position count (`_decPositionCount`, ~3272). `_moves` (~2354) never reads `_halfMoves`/`_moveNumber`. A position built from a FEN and moved once has position count 1 for the child, same as `new Chess(childFen)`, so threefold cannot fire either way. A planning-time script checked 146 moves across en passant, promotion, castling, mate and fifty-move FENs: shared-instance move/fen/undo matched fresh `new Chess(childFen)` on fen(), isGameOver(), isCheckmate() and turn() with 0 mismatches.
- Maia encoding reads only FEN fields 1-2: `frontend/src/lib/maiaEncoding.ts` `encodeBoard` (~177-188) and `frontend/public/maia/maia-worker.js` `encodeBoardTokens` (~234-240). Legal-move masking (`maskAndSoftmaxUci`, `buildPolicyMoveContext`) uses `new Chess(fen)`, which depends on fields 1-4 (castling and ep change legal moves) but not on the counters.
- chess.js 1.4 `fen()` prints an ep square only when an ep capture is actually legal, so two chess.js-produced FENs for one position agree on field 4.
- The worker's `analyze()` builds every per-rung array with `TypedArray.prototype.slice`, which allocates a fresh, non-shared ArrayBuffer per slice. Those buffers are owned and distinct, so they can go in a transfer list (no duplicate-buffer or SharedArrayBuffer DataCloneError).
- The grade pool resolves `new Map()` on: abort (`workerPoolDispatch.ts` ~177), empty pool (~197), no live slot (~211), and watchdog/lifecycle fires (`workerPoolWatchdog.ts` ~169/213, `workerPoolLifecycle.ts` ~115/194/297/305/318/323).

- The only writer of the shared pending registry is `useMaiaEngine` (`markPolicyPending`). maiaQueue never marks entries pending, and each maiaQueue `pending` entry has exactly one waiter (its own policy() call). Removing an aborted maiaQueue entry therefore never strands another waiter.
