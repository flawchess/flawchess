# Quick 261120-li5: drop the redundant outer ranked-id `ANY` predicate in endgame queries

## Problem

`GET /api/endgames/ranked-stats` (and the endgame insights that share `fetch_ranked_inputs`)
intermittently takes 15-110 s on prod (Sentry 30 d: p50 531 ms, p95 82 s, max 110.6 s on
2026-11-13). The four endgame row queries restrict to the ranked-sample game ids twice:
inside the grouped `game_positions` aggregation (the selective filter) and again on the outer
`games` query via `apply_game_filters(..., game_ids=game_ids)`. The outer copy is redundant
(the join / `IN` on `games.id` already limits rows to the inner set), but the planner
multiplies `user_id` x `ANY` x platform selectivities into a 1-row estimate for `games`, picks
a nested loop with `games` outer, and re-executes the whole aggregate once per ranked game.

Prod measurement (user 1388, 1,435 literal ranked ids, `query_clock_stats_rows` shape):
- as shipped: 14,510 ms, 6.56 M shared buffers (aggregate loops=1435)
- outer predicate removed: 30 ms, 8.9 k buffers (aggregate loops=1)

## Tasks

### Task 1: drop the outer `game_ids` filter where it is redundant

- **files:** `app/repositories/endgame_repository.py`
- **action:** pass `game_ids=None` to `apply_game_filters` in `query_endgame_entry_rows`,
  `query_endgame_bucket_rows`, `query_clock_stats_rows`, and the endgame (`IN` subquery) half
  of `query_endgame_performance_rows`. Keep `game_ids=game_ids` on the non-endgame (`NOT IN`)
  half, where the outer predicate is the only ranked-id restriction. Comment each fix site
  (what broke, measured numbers, "do not add back").
- **verify:** `uv run pytest tests/test_endgame_repository.py tests/services/test_insights_service.py -q`
- **done:** results unchanged; the outer predicate is absent from the three join queries and
  the endgame half.
