# Quick 260916-g38: Sentry noise — Maia page-kill idle guard, full-drain breaker single-target guard

Two unresolved Sentry issues that fire on shapes the instrumentation was not designed for.

## Task 1: Maia page-kill sentinel idle guard (FLAWCHESS-BM)

**Files:** `frontend/src/lib/engine/maiaPageKillSentinel.ts`, `frontend/src/lib/engine/__tests__/maiaPageKillSentinel.test.ts`

**Evidence:** Android 10 tablet, wasm backend, 4 threads, session 55 min old, 53 min since the last Maia dispatch when the record survived. A foreground kill that long after Maia last ran (app swiped from recents, OS reclaiming an idle page) says nothing about Maia inference memory. The sentinel exists for the iOS WebKit per-page memory kill that happens seconds after a dispatch.

**Action:** in `reportMaiaPageKillFromPreviousSession`, when `sinceLastDispatchMs` is non-null and exceeds `MAIA_PAGE_KILL_IDLE_THRESHOLD_MS` (10 min), clear the record and return `false` without capturing. A record with `last: null` (armed, never dispatched) is still reported — an arm-then-kill is the iOS shape.

**Verify:** `npm test -- --run src/lib/engine/__tests__/maiaPageKillSentinel.test.ts`

## Task 2: Full-drain breaker single-target guard (FLAWCHESS-5Q)

**Files:** `app/services/eval_drain.py`, `tests/services/test_full_eval_drain.py`

**Evidence:** game 2494493 (2 plies, chess.com): both plies dedup-hit the opening cache, so the only engine target was the terminal donor. One transient failure made "all evals failed" true and tripped the WR-05 pool-outage breaker. The game self-healed 56 min later on re-pick. With one target the breaker cannot distinguish an outage from a one-off.

**Action:** add `FULL_DRAIN_BREAKER_MIN_TARGETS = 2`; the breaker fires only when `len(engine_targets) >= FULL_DRAIN_BREAKER_MIN_TARGETS` and all failed. A lone failed target falls through to the per-position mark-and-continue path (hole, stamp withheld, attempts incremented, re-picked next tick).

**Verify:** `uv run pytest tests/services/test_full_eval_drain.py -k "all_fail or breaker"`; new tests: single failed target does not trip the breaker (no Sentry message, attempts → 1); exactly two failed targets still trip it.
