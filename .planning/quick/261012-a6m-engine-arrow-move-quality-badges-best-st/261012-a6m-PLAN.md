<objective>
Engine arrows tell the user how good each move is. The top Stockfish arrow carries the best-move star. Each secondary Stockfish arrow carries its move-quality badge (good / inaccuracy / mistake / blunder), graded against the top line through the app's existing expected-score pipeline. It also fades in proportion to how much worse it is (D-08), and its badge uses the same opacity. This ships on the Analysis page and on the Train solution's stepped-preview and free-play boards.

Purpose: owner request (CONTEXT.md D-01..D-08). Today a secondary arrow is just a translucent blue line. The user cannot tell whether the second engine move is nearly as good or a blunder.

Output: a new pure shared module `frontend/src/lib/engineArrowGrades.ts` (one grade computation per position yields per-rank {quality, alpha}), wired into `useAnalysisBoardArrows` and the Train arrow builders, with unit tests, page-test fixups and a CHANGELOG bullet.
</objective>
