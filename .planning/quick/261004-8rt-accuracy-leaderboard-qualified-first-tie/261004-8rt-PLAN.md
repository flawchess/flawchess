<objective>
Fix the weekly Accuracy leaderboard ordering: rank qualified users first, list tentative users
below them with no rank number, and adjust the viewer standing, the "(up N)" delta and the
landing card to match.

Owner decision (2026-10-04, supersedes Phase 230 D-03 in
`.planning/phases/230-weekly-train-leaderboards/230-CONTEXT.md`, which said "Tentative users ARE
ranked and listed"; Phase 230's "expect Monday's Accuracy top to be short 100% sessions; accepted"
is reversed too). Prod on Sunday 2026-10-04 showed five "#1 100% 1 puzzle (tentative)" rows above
every qualified player.

Purpose: the Accuracy board is meaningless while a single lucky solve outranks a qualified week of
work. Tiering also lines the live board up with Phase 231 / SEED-186 ("Accuracy medals for
qualified users only; final standings skip tentative users"), so a later medal snapshot can read
ranks straight off the board.

Output: tiered backend ranking with nullable ranks on the wire, a frontend that renders unranked
rows under a "Not yet qualified" divider, updated score-screen copy, tests, and a CHANGELOG bullet.

Structure note: tracer-first is not applied. The endpoint, service and card shipped in Phase 230
and are proven end to end; this is a ranking-contract change, so the plan follows the
orchestrator's split (backend contract, then frontend consumer, then the gate). Task 2 depends on
Task 1's wire contract (nullable rank).
</objective>
