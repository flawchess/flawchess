# Backend Maia session: one intra-op thread

## Problem

During the Phase 252 prod re-walk the prod server (8 cores) sat at 100% CPU, load
average 15, with Postgres idle. Caddy timings over 10 minutes: `flaw-blob-submit`
median 1.88 s, p95 5.25 s, about 2.6 submits in flight; all leases under 0.11 s.
Each submit runs the Maia re-score inline (`app/routers/eval_remote.py`), and the
lifespan started the Maia session with ONNX Runtime's default thread count (one
per core), so concurrent submits contended for every core.

## Change

- `app/core/config.py`: `MAIA_INTRA_OP_THREADS: int = 1` (0 = ORT default).
- `app/main.py`: lifespan passes it to `start_maia` via `_maia_intra_op_threads()`.
- `app/services/maia_engine.py`: docstring only.
- `tests/services/test_maia_engine.py`: default is 1; 0 maps to None.

## Verify

- New test fails when the default is reverted to 0 and when the helper is broken.
- Full pre-merge gate.
- After deploy: prod backend CPU and `flaw-blob-submit` latency against the numbers above.
