<objective>
Rebalance blunder-check scoring so a session's Score % reflects the whole skill (safe-move judgement, catching, finding the better move) instead of being roughly the catch rate. Prod evidence (86 completed sessions): safe-move accuracy 88%, catch rate 48%, better move 1.41/2 after a catch; replaying those sessions under the rules below gives mean 63.3% (median 64%), up from about 50%.

Locked decisions (owner-approved, NON-NEGOTIABLE; the D-numbers are the order of the task description):
- D-01: point ratio safe : blunder flag : better move = 1 : 2 : 1, every value doubled to stay integer. SAFE_POINTS 1 -> 2, BLUNDER_POINTS 3 -> 4, SAFE_TIMEOUT_PENALTY_POINTS 1 -> 2; the better move stays graded exactly like a puzzle via MOVE_TIER_POINTS (good 2 / inaccuracy 1 / wrong 0), so BETTER_MOVE_POINTS stays 2. Points possible: herring = 2 * length; blunder window = 2 * (blunder_position - 1) + 4 + 2.
- D-02: a missed blunder ("safe" call on the blunder) no longer forfeits the window's accumulated safe points. A TIMEOUT on the blunder still forfeits them (stalling must cost). Comment the change at the fix site.
- D-03: the better-move task is offered after a missed blunder too (outcome "missed", by a "safe" call or a timeout), graded identically to after a catch (same better_move_graded_moves / resolve_better_move_tier derivation, same points). The user sees that the move was a blunder, then gets "find the better move". Reveal ordering must not leak the key or the solution before the better move is graded (same as the caught path). A false alarm still ends the window with no better-move task.
- D-04: an Alembic data migration rescales open sessions at deploy: for windows of sessions with status 'open' whose outcome IS NULL, set points_possible to the new formula and double points_awarded / points_forfeited on their answer rows and the window's points_scored. Ended windows keep their old-scale values. Downgrade reverses it. Chain from the current head a7c3e5f9b261.
- D-05: update every user-facing explanation of points (rules / intro text, frontend/src/types/blunderCheck.ts comments, points flash, any forfeit explanation that now applies only to timeouts on the blunder). Server-side copy in app/services/blunder_check_feedback.py was checked at planning time: it holds only the type line and the hard-to-catch facts, no points copy, so it needs no change.
- D-06: one user-facing CHANGELOG.md bullet under [Unreleased] ### Changed (the section exists).
- D-07: app/services/train_leaderboard.py gets no code change; the blunder-check Points board shows larger numbers from the deploy on. Do not rescale history.

Out of scope (do not touch): the facepalm cut, the window mix, the timer, scripts/blunder_check/ reports.

Purpose: Score % should land near the personalized-puzzle band (target 65-75%), and a wrong call should cost the call, not the whole sequence.
Output: rescaled constants and grading, a better-move step after a miss (backend and frontend), a one-deploy data migration, updated copy, tests, and a CHANGELOG bullet.
</objective>
