# Blunder-check peer legs (exploratory measurement)

Run 2026-11-10 on prod data, local Maia + Stockfish (1,000,000 nodes per search). Not wired into app code. See SEED-261110-p7k.

## Definitions

Both legs are the same calculation on two positions: the expected loss of the side to move, i.e. Maia probability (at the user's pinned Elo) times expected-score loss against that side's best move, summed over the likely moves (Maia's top moves, up to 8, covering 90% of the probability; scaled to the evaluated share).

- **Engine drop:** the user's expected-score loss when the opponent plays the engine's best reply. This is the usual blunder measure: a blunder loses at least 0.15 (mistake 0.10, inaccuracy 0.05). Re-computed here, so it can differ slightly from the stored value.
- **Expected loss (leg 1, `maia_expected_loss`):** at the blunder ply, user to move. How much a peer loses in this position on average. Low = peers handle the position.
- **Reply loss (leg 2, `maia_reply_loss`):** at ply + 1, opponent to move. How much of the blunder a peer opponent gives back on average. Low = peers punish the blunder.
- **Practical loss:** engine drop minus reply loss: what the blunder costs against a peer's replies. Needed because reply loss alone ignores how big the blunder is.
- **Rule tested:** expected loss <= 0.1 and practical loss >= 0.15.
- **Current rule:** D-06 from stored columns, with every miss treated as mixed (either test passes), so it slightly overstates the current pass rate.
